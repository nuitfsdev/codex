# Weekly Research Shortlist — 2026-W38

Project: 3D Scene Understanding with 2D Vision-Language Models via Abstract 3D Representations and Viewpoint Alignment
Updated: 2026-09-19

## Ranking

### 1. SAFER-QA / QASER-CF — Constraint-first QA-specific evidence retention
**Current top candidate.**

Pipeline:
`question -> seed hypotheses -> relation/question-type parser -> constraint-first global candidate generation -> QA-support evidence allocation -> PoseAlign-T -> selective Abstract3D rendering -> <=7B VLM`

Key thesis claim: select the minimal/compact object subset that preserves QA evidence, including unnamed supporting/context objects, **before rendering**. Do not use generic semantic Top-K, KNN or radius as an early universal gate.

Scores (1-5; Compute Cost higher=cheaper): Novelty 3.5; Expected Accuracy Gain 3.8; Feasibility 4.7; Compute Cost 4.9; Fit 5.0; Evidence Strength 4.7.
Targets: ORR 50-85%; QEC >=95%; SCR high under matched object budget; context-loss risk medium with fallback expansion.

### 2. QASER-CG — Constraint-Graph Support Selection
Preferred structured implementation of QASER-CF after CitySTAR. Parse question into seed/referred nodes, relation/attribute constraints and wildcard/latent support nodes; globally match against a lightweight graph from fixed object labels/3D boxes. Retain unnamed objects when they complete a constraint path, disambiguate a seed, or are required relation endpoints. Geometry verifies query-specific predicates rather than acting as a universal KNN/radius gate.

Scores: Novelty 3.3 standalone / 3.7 integrated; Expected Gain 4.0; Feasibility 4.7; Compute Cost 4.9; Fit 5.0; Evidence 4.7.
Targets: ORR 50-85%; QEC >=95%; SCR higher than semantic Top-K/KNN at matched K; context-loss risk medium.

### 3. QASER-R — recovery-gated supporting-object expansion
Run QASER-CF cheaply first; only if retained evidence is insufficient/ambiguous/conflicting, add omitted annotated support objects or an aligned view. Unlike Finder, no online detector/exploration is required: recovery operates over fixed object annotations/3D boxes. Preferred refinement for controlling context-loss without iterative VLM cost on every sample.

Scores: Novelty 3.2 standalone / 3.7 integrated; Expected Gain 4.0; Feasibility 4.5; Compute Cost 4.3; Fit 5.0; Evidence 4.5.
Targets: ORR 50-80%; QEC >=95%; SCR higher than fixed-K at matched average budget; explicitly measure recovery rate, recovered-answer rate, average rendered objects and VLM calls.

### 4. QASER-Div — diversity-reserved support allocation
After QASER-CF global candidate generation, reserve part of the object budget for distinct supporting hypotheses using frozen feature-space diversity (DPP or greedy diversity), while hard-retaining seeds and relation-conditioned candidates. Motivated by 3DZip/CoVeR evidence that relevance-only or spatial-only compression can lose coverage. This is an integrated refinement, not a standalone headline contribution.

Scores: Novelty 3.2 standalone / 3.7 integrated; Expected Gain 3.7; Feasibility 4.8; Compute Cost 4.9; Fit 5.0; Evidence 4.8.

### 5. UGSE — Uncertainty-Gated Support Expansion
Adaptive object budget: start with the compact QASER-CF set, expand support only if evidence is ambiguous/missing/conflicting. QASER-R supersedes this as the more concrete implementation formulation after Finder.

Scores: Novelty 3.0 standalone / 3.4 integrated; Expected Gain 3.5; Feasibility 4.2; Compute Cost 3.6; Fit 4.8; Evidence 4.2.

## First-tier baselines / novelty limiters
- **CitySTAR (arXiv 2609.19911, submitted 2026-09-17):** training-free open-vocabulary urban 3D grounding. Converts language into computable entity/attribute/spatial constraints, uses target-context topology with paired hypergraphs and bidirectional topology verification, then candidate-centered 2D evidence. Strong new evidence for constraint-first selection, but also a novelty limiter for generic `language -> structured constraints -> graph matching` claims. Domain is city-scale grounding, not ScanQA/SQA3D; official code not verified as of 2026-09-19.
- **Finder (arXiv 2609.18058, submitted 2026-09-16):** agentic closed-loop object finding with primary + optional supporting objects and accept/continue/abort control. Not ScanQA/SQA3D and detector-dependent in its original setting. Strong limiter for generic closed-loop support retrieval claims.
- **MSSR (ICLR 2026):** training-free Minimal Sufficient Set reasoning with iterative prune/request-missing-evidence loop; code public. Strong limiter for generic minimal sufficiency and iterative evidence-refinement claims.
- **GraFT (2026-09-03):** training-free; direct ScanQA evaluation; compact 3DSG with symbolic geometry, allocentric BEV and task-relevant egocentric visual grounding. Limits novelty of generic scene graph + tools + task-relevant views.
- **CAPruner (ACL 2026):** peer-reviewed relation/edge pruning baseline and possible support-candidate generator; not a complete QA object selector.
- **PruneGround (2026-06-30):** frozen-VLM language-guided spatial pruning and visual-anchor expansion; major novelty limiter for generic pruning/unnamed-anchor discovery, but objective is 3D grounding rather than open-ended QA evidence retention.
- **AgentGrounder (2026-05-25):** semantic-first retrieval + geometry baseline; useful to test early semantic hard-gate failures.
- **SeGPruner:** direct ScanQA evidence that semantic saliency plus geometric coverage can preserve performance under aggressive token reduction.
- **3DZip (ECCV 2026):** training-free; code public; ScanQA/SQA3D/OpenEQA. Feature-DPP + spatially constrained merging; evidence that diversity/object coverage matters under strict token budget. Token-level, not an object selector.
- **CoVeR (2026-09-08 preprint):** training-free deterministic spatial-coverage token pruning on ScanQA/SQA3D/OpenEQA. Token-level novelty limiter for generic coverage-aware pruning.
- **CoV / IVSGround:** view-selection baselines; view selection should remain secondary, not the main novelty.

## Matched-budget ablation priority
`Full Scene` vs `GraFT near-task baseline` vs `semantic Top-K` vs `Seed+KNN` vs `Seed+radius` vs `CAPruner endpoints` vs `PruneGround-style expansion` vs `QASER-CF flat constraint scoring` vs `QASER-CG constraint-graph matching` vs `QASER-CG without wildcard/support nodes` vs `QASER-CF + diversity reserve` vs `QASER-R deterministic recovery` vs `QASER-R + VLM sufficiency judge` vs `+PoseAlign-T`.

## Weekly conclusion so far
SAFER-QA / QASER-CF remains #1. CitySTAR provides fresh evidence for the constraint-first premise but narrows the novelty boundary: structured constraint reasoning/topology matching alone is no longer a defensible headline claim. QASER-CG is now the preferred structured implementation for candidate generation and unnamed-support retention; QASER-R remains the preferred recovery mechanism. The thesis gap remains **QA-specific object/subscene evidence retention before Abstract3D rendering from fixed annotations, under a strict object/render budget, explicitly preserving unnamed supporting evidence on ScanQA/SQA3D and using PoseAlign-T for viewpoint-dependent verification**.
