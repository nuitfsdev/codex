## Candidate A — Pose/Diversity View Selection after Object Subscene Selection

Source: SpatialPrompting: pose-aware keyframe prompting for 3D spatial QA toward smart indoor environments. Frontiers in Robotics and AI, 2026-07-14. Peer-reviewed. Public code: ToyotaCRDL/SpatialPrompting. Evaluated on ScanQA and SQA3D; model-agnostic, training-free; includes Qwen2.5-VL-7B experiments.

Research Hypothesis: After OLT-QA reduces the scene to a compact object subscene, a small set of pose-diverse, visibility-aware abstract views can preserve or improve QA while reducing redundant rendered views.

Stage changed: post-object-selection view selection / multi-view aggregation.

Object-selection rule: none; consumes the already selected object subset. Do not use this as the thesis object selector.

Supporting-context rule: hard-preserve all selected seed/support objects and score candidate views by coverage of the retained support set, pose diversity, FOV, and image quality. Adapt SpatialPrompting's keyframe criteria from raw RGB frames to abstract renders.

Expected benefit: fewer redundant views; better viewpoint coverage; stronger robustness for spatial relation and intermediate-object questions.

Implementation difficulty: low-medium. Requires generating a candidate bank of abstract views and computing simple coverage/diversity/quality scores.

Data/metrics: ScanQA/SQA3D; EM@1/CIDEr/ROUGE-L as applicable; number of rendered views; visual-token count; latency; selected-object visibility coverage.

Compute estimate: no training. View scoring is lightweight. Main compute is 2D VLM inference over selected abstract views. Qwen2.5-VL-7B is directly supported by the source paper; practical VRAM depends on quantization/image count, so no fixed paper-derived VRAM claim is made.

Ablations: canonical PoseAlign-T view only; uniform K views; question-similarity-only views; pose-diverse views; support-coverage + pose-diversity views; with/without view verbalized pose.

Risks: generic pose-aware keyframe selection is already established by SpatialPrompting, so novelty is low unless coupled specifically to selected abstract subscenes and support-object visibility. Standard ScanQA/SQA3D may under-stress multi-view reasoning.

Publication potential: secondary module / strong ablation, not main novelty.

Scores (1-5): Novelty 2.0; Expected Accuracy Gain 3.5; Feasibility 4.5; Compute Cost 4.0 (higher=cheaper); Fit 4.5; Evidence Strength 5.0.

## Candidate B — Global/Local Evidence Verification for Selected Objects

Source: UniGround: Universal 3D Visual Grounding via Training-Free Scene Parsing, arXiv 2603.08131; v2 revised 2026-08-12. Preprint. No verified official code link on arXiv as of this scan. The paper is training-free at the task level and uses Global Candidate Filtering plus Contextual Precision Grounding with global scene renderings, candidate-centric RGB evidence, relation parsing, and consistency correction. Its reported main VLM setting uses GPT-5, outside the thesis <=7B target.

Research Hypothesis: For a compact QA subscene, combining an aligned abstract global view with a small number of candidate-centric native RGB crops can recover appearance evidence lost by abstraction without reintroducing full-scene clutter.

Stage changed: after OLT-QA + PoseAlign-T; evidence construction / spatial verification.

Object-selection rule: retain OLT-QA selected seed + support objects; optionally rank seed instances with multi-view semantic similarity. Do not copy UniGround's segmentation/candidate-construction stage because GT boxes are fixed input in this thesis.

Supporting-context rule: global abstract view must render the entire selected support set; local crops are attached only to ambiguous seed/candidate objects. Never replace global support context with candidate crops.

Expected benefit: better color/material/fine-appearance answers while keeping geometry and inter-object relationships explicit in the abstract global view.

Implementation difficulty: medium. Requires mapping GT object IDs to native ScanNet RGB frames and selecting high-coverage/diverse crops.

Data/metrics: ScanQA/SQA3D QA; appearance-vs-spatial question slices; object/view count; token/latency budget; QA preservation under subscene reduction.

Compute estimate: no 3D/task-specific training. Local crop extraction and embedding are lightweight; VLM cost increases with the number of crops. The source paper's GPT-5 configuration is not transferable as-is to the <=7B constraint.

Ablations: abstract-global only; local-crops only; abstract-global + local crops; crops for all selected objects vs ambiguity-triggered crops; with/without consistency verification.

Risks: UniGround already covers global + candidate-local evidence and semantic-spatial consistency in 3D grounding, so this is not standalone novelty. Using raw RGB crops may also weaken the simplicity of an abstract-only story.

Publication potential: secondary evidence-recovery/verification module.

Scores: Novelty 2.5; Expected Accuracy Gain 4.0; Feasibility 3.5; Compute Cost 3.0; Fit 4.0; Evidence Strength 4.0.

## Object-selection track implications

SpatialPrompting does not solve object/subscene selection. UniGround's instruction-to-candidate cosine similarity/top-u filtering is useful as an object-retrieval baseline, but it targets a referred object rather than QA support. Neither source resolves the key distinction needed here:

- Seed objects: explicitly referred/anchor entities from the question.
- Supporting/context objects: possibly unnamed objects needed to answer, compare, count, establish relations, or disambiguate the seed.

Therefore OLT-QA should not collapse to semantic top-K or exact noun match. Supporting-context retention remains the central unresolved component.

Recommended object-selection ablation state:
1. Full scene.
2. Explicit seed objects only.
3. Semantic top-K / UniGround-style instruction similarity.
4. Seed + KNN.
5. Seed + relation-aware supporting expansion.
6. Seed + relation-aware expansion + post-PoseAlign-T directional refinement.
7. Optional diversity-preserving support selection under a fixed object budget.

Metrics to retain: Object Reduction Ratio; Question Entity Coverage; Supporting-Context Retention proxy/diagnostic; context-loss failure rate; downstream ScanQA/SQA3D QA preservation.
