# Daily Proposal Research — 2026-09-06

## New high-impact paper: GraFT

**GraFT: A Training-Free Framework for Spatial Reasoning in Multimodal Large Language Models via 3D Scene Graphs** — arXiv:2609.03892v1, submitted 2026-09-03. Status: preprint; no peer-reviewed venue verified. No official code repository verified as of 2026-09-06.

Paper: https://arxiv.org/abs/2609.03892

### Why this materially changes the shortlist
GraFT is unusually close to the thesis setting:
- training-free;
- accepts a 3D scene graph whose object nodes contain class labels and 3D boxes;
- explicitly evaluates a ground-truth-perception setting built from ScanNet annotations;
- uses frozen Qwen2.5-VL-7B and Qwen2.5-VL-3B in experiments;
- uses deterministic geometry, selective BEV rendering, and geometry-ranked egocentric frame retrieval;
- evaluates ScanQA directly.

Most importantly, its BEV module already **renders only query-relevant/referenced objects and omits the rest**. Algorithm 1 obtains `RelevantClasses(q)` using regex+synonyms or a VLM selector over the scene-graph class list. The egocentric module similarly resolves target objects from the question by class name and ranks only frames that reveal those queried objects.

Therefore the thesis must not claim as novelty:
- question -> relevant class extraction;
- selective rendering of only referenced objects;
- task-conditioned BEV alone;
- geometry-guided view selection alone;
- symbolic geometry over object boxes alone.

### Verified evidence
- ScanQA with frozen Qwen2.5-VL-7B: uniform 8-frame baseline CIDEr 58.0; geometry-selected top-1 69.2; top-2 73.6; top-3 75.9.
- The paper reports BLEU-1 22.2 -> 34.2 and CIDEr 58.0 -> 73.6 for its default top-2 ScanQA setting.
- On VSI-Bench, Qwen2.5-VL-7B + GraFT reaches 50.0 average under realistic perception; Qwen2.5-VL-3B reaches 47.5.
- Hardware/VRAM is not reported in the paper; training cost is zero, but inference VRAM follows the chosen frozen VLM plus rendering/tool overhead.

## New candidate: SAFER-QA

**Support-Aware Evidence Expansion for Selective Abstract 3D Rendering**

### Research Hypothesis
GraFT-style referenced-object selection removes clutter but is incomplete for open-ended 3D QA because an answer may depend on unnamed supporting/context objects. Starting from explicit seed/referred objects, a lightweight relation-conditioned expansion can preserve the smallest useful context set, and PoseAlign-T can subsequently prune viewpoint-dependent candidates before Abstract-3D rendering.

### Stage changed
Question-conditioned object/subscene selection between fixed GT object boxes and PoseAlign-T / Abstract Renderer.

### Object-selection rule
1. Build an object table from fixed ScanNet GT boxes: id, class, center, extent, optional color/RGB summaries.
2. Parse question into explicit seed classes/entities, attributes and relation intent.
3. Resolve all plausible seed instances using class/synonym/frozen semantic similarity; do not collapse same-class ambiguity too early.
4. Hard-retain seeds.
5. Add supporting objects through relation-conditioned graph expansion under a fixed object budget.
6. After PoseAlign-T, recompute left/right/front/behind and remove geometrically incompatible supports.
7. Render only the retained subscene.

### Supporting-context rule
Supports do **not** need to appear as nouns in the question. Candidate supports can enter via one-hop relations from seeds (near, above/below, support/contact, containment, overlap, same functional cluster). Permit a second hop only when the question implies a chained relation and confidence is high. Use diversity-aware tie-breaking when the budget is exceeded so KNN does not retain redundant same-type objects.

### Expected benefit
- retain unnamed answer evidence better than referenced-object-only selective rendering;
- reduce clutter relative to full-scene rendering;
- preserve or improve downstream ScanQA/SQA3D QA at substantially lower object count;
- combine naturally with PoseAlign-T for directional pruning.

### Difficulty / compute
Implementation difficulty: medium. No new training is required. Pairwise box relations and graph expansion are CPU-cheap. Main VRAM cost remains frozen 2D VLM inference; Qwen2.5-VL-3B/7B is feasible relative to training 3D models. Exact VRAM should be measured rather than claimed because GraFT does not report it.

### Evaluation without ScanQA relevance annotations
Do not use ScanQA object relevance/object IDs as selector supervision or target labels. Measure:
- downstream ScanQA/SQA3D QA metrics;
- Object Reduction Ratio;
- Question Entity Coverage based on whether parsed explicit entities resolve to at least one retained instance (self-contained parser metric, not ScanQA relevance GT);
- **Context Benefit Rate**: fraction of questions where Seed+Support succeeds but Seed-only fails;
- **Support Ablation Sensitivity**: QA drop after removing selected support objects while keeping seeds;
- object-budget vs QA curve.

`Supporting-Context Retention` cannot be a literal GT recall metric without a supporting-object GT set. Report it as a proxy derived from Context Benefit Rate / Support Ablation Sensitivity, and label it explicitly as a proxy.

### Required ablations
1. Full scene.
2. GraFT-style referenced/seed-only selection.
3. Seed + KNN.
4. Seed + radius.
5. Seed + relation-conditioned support expansion.
6. + diversity-aware support budget.
7. + PoseAlign-T directional refinement.
8. Same object budget for KNN/radius/relation-aware variants.

### Risks
- Relation graph may reduce to generic scene-graph retrieval; novelty depends on demonstrating QA-specific unnamed-support retention.
- Supporting evidence is not exhaustively annotated in ScanQA, so context metrics require careful proxy wording.
- For questions whose answer is purely an attribute of the named object, support expansion may add unnecessary clutter.
- If Seed-only matches Full Scene on most ScanQA questions, the proposed support-expansion contribution is weakened.

### Scores (1-5)
- Novelty: 3.5
- Expected Accuracy Gain: 3.5
- Feasibility: 4.5
- Compute Cost (higher = cheaper): 4.5
- Fit with proposal: 5.0
- Evidence Strength: 4.5

- Question Entity Coverage: target >=95% for explicit entities (experiment target)
- Supporting-Context Retention: unknown; evaluate with proxy metrics above

## Effect on existing candidates
- **OLT-QA:** seed lookup itself is now much less novel because GraFT already performs question-to-relevant-class selection. Keep OLT only as the seed-retrieval front end of SAFER-QA.
- **RCSX:** strengthened and promoted conceptually; relation-conditioned support expansion is now the part that differentiates the thesis from GraFT's referenced-object-only rendering.
- **Question-aligned view selection:** remains secondary/ablation; GraFT, CoV and SpatialPrompting already provide strong precedent.
- **3DZip diversity selection:** remains useful as a tie-breaker within the support budget, not as the main contribution.

## Top candidate of the week
**SAFER-QA: Support-Aware Evidence Expansion for Selective Abstract 3D Rendering.**

Reason: GraFT newly establishes a very strong, near-direct baseline for training-free selective rendering of *referenced* objects using a frozen <=7B VLM and ScanNet/ScanQA-compatible geometry. That removes much of the novelty of seed-only relevance selection, but simultaneously sharpens the unresolved gap: preserving **unnamed supporting objects** under an aggressive Abstract-3D object budget. The thesis should now center the object-selection contribution on this gap rather than generic relevance retrieval.
