# Daily Proposal Research — 2026-09-08

## New evidence retained

### SeGPruner — Semantic-Geometric Visual Token Pruner for 3D Question Answering
- arXiv: 2603.29437 (2026-03-31); public code: `intcomp/SegPruner`.
- Directly evaluates ScanQA and OpenEQA with LLaVA-OneVision-Qwen2-7B.
- Training-free at inference/module level: keeps semantic-salient visual tokens, then restores spatial coverage through 3D geometry-guided diversity.
- Reported headline: up to 91% visual-token reduction and 86% inference-latency reduction while preserving competitive 3D-QA performance; moderate retention can slightly improve EM by removing redundancy/noise.

### Transfer candidate: Object-Level Evidence Allocation (OLEA)
**Research Hypothesis:** the SeGPruner principle should be moved one level earlier, from visual-token selection to GT-object selection: first hard-retain question seeds, then allocate the remaining object budget across complementary support roles (semantic/relation-critical + spatially diverse context) rather than KNN-only support.

**Stage changed:** SAFER-QA support-budget allocation before Abstract-3D rendering.

**Object-selection rule:**
1. Hard-retain resolved seed/referred objects.
2. Score support candidates with relation compatibility / semantic evidence.
3. Reserve a fraction of the object budget for spatially diverse context using 3D center distance or coverage.
4. Apply PoseAlign-T before pruning viewpoint-dependent candidates.
5. Render only the selected seed+support objects.

**Supporting-context rule:** support objects can enter even when absent from the question if they either satisfy a relation-compatible role or improve geometric/context coverage under the fixed object budget.

**Expected benefit:** lower context-loss risk than semantic Top-K / seed-only / KNN at the same object count, while preserving the key thesis objective of not rendering the whole scene.

**Difficulty:** low-to-medium. Requires only GT boxes, relation scoring, and budget allocation; no detector/segmentation training.

**Compute estimate:** negligible selector overhead relative to VLM inference; expected VRAM dominated by <=7B VLM. No daily GPU benchmark required.

**Metrics:** ScanQA/SQA3D QA; Object Reduction Ratio; Question Entity Coverage; object-budget-vs-QA curve; Context Benefit Rate; Support Ablation Sensitivity. Supporting-Context Retention remains proxy-only without an explicit support GT set.

**Ablation:** Seed-only vs Seed+KNN vs Seed+relation vs Seed+diversity vs Seed+relation+diversity vs +PoseAlign-T, matched object budget.

**Risks:** diversity can keep irrelevant distant clutter; semantic saliency from VLM attention cannot be copied directly at object level; gains may collapse if relation candidates already cover enough context.

**Scores (1-5):** Novelty 3.0 standalone / 3.7 inside SAFER-QA; Expected Accuracy Gain 3.5; Feasibility 4.7; Compute Cost 4.8 (higher=cheaper); Fit 5.0; Evidence Strength 4.6.

**Object-selection diagnostics:** target Object Reduction Ratio 50-85% (test target, not claim); Question Entity Coverage >=95% target; Supporting-Context Retention unknown/proxy-only; context-loss risk medium-low relative to seed-only/KNN if the budget allocator works.

**Publication potential:** moderate-to-good as an integration contribution only if matched-budget experiments show that dual evidence allocation at object level preserves QA better than KNN/semantic-only while materially reducing rendered objects.

## New novelty limiter / secondary evidence

### IVSGround — Where to Look Matters: Learning Influential Views for VLM-based 3D Visual Grounding
- arXiv: 2609.04741, submitted 2026-09-04; evidence indicates ECCV 2026 main-conference presentation.
- Learns query-conditioned influential views per candidate object rather than using visibility heuristics.
- Uses a LoRA-fine-tuned Qwen3-VL-8B view selector and a frozen Qwen3-VL-32B reasoning VLM in reported configurations; evaluated on ScanRefer and NR3D.
- Therefore it is strong evidence that view relevance matters, but it violates the preferred training-free / <=7B main-method scope and is not directly ScanQA/SQA3D.
- Consequence: learned query-conditioned view selection is baseline/related work, not novelty. Keep training-free view selection after SAFER-QA as a secondary module.

## Top candidate of the week
**SAFER-QA remains #1**, now strengthened by an object-level analogue of SeGPruner's semantic-plus-geometric budget allocation:

`seed retrieval -> relation-aware support + co-visibility -> fixed-budget semantic/relation + spatial-diversity allocation -> PoseAlign-T refinement -> selective Abstract-3D render -> <=7B VLM`

Reason: SeGPruner provides direct ScanQA evidence that preserving salient evidence while explicitly maintaining geometric diversity is superior to one-dimensional pruning under tight budgets. It does not solve object-level unnamed-support selection, so it strengthens rather than supersedes the SAFER-QA gap. IVSGround further reduces the novelty of learned view selection but does not challenge the support-aware object-selection contribution.
