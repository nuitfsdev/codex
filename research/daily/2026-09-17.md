# Daily Proposal Research — 2026-09-17

## High-value update: 3DZip as evidence for diversity-aware evidence budgets

3DZip (ECCV 2026; arXiv:2608.01185; code public) is a training-free 3D-QA token-compression method evaluated on ScanQA, SQA3D and OpenEQA. It uses coarse voxelization, feature-space diversity via DPP anchor selection, then spatially constrained merging. Reported result: 94.7% of full performance with 128 tokens and 1.92x faster inference. The official repo includes ScanQA/SQA3D evaluation scripts.

Important transfer insight for our pipeline: pure spatial coverage and pure semantic/query relevance are both insufficient selection principles. 3DZip reports that feature-DPP improves object coverage relative to XYZ-DPP (project page: 64% vs 47% on SQA3D test scenes). This does NOT directly validate object selection, because 3DZip operates at token level after feature construction. It does provide strong evidence that a fixed evidence budget should avoid redundant candidates and preserve representation across distinct object hypotheses.

## Candidate improvement: QASER-Div — relation-first + diversity-reserved object budget

Hypothesis: after constraint-first global candidate generation, selecting all support objects by a scalar relevance score causes redundant objects/categories/regions to consume the object budget. Reserving part of K for diverse supporting hypotheses can improve QA evidence retention at the same render budget.

Stage changed: question-conditioned object selection immediately before PoseAlign-T / Abstract3D rendering.

Rule:
1. Hard-retain seed objects explicitly grounded from the question.
2. Generate support candidates globally using question/relation constraints; do not use KNN/radius or semantic Top-K as a universal hard gate.
3. Fill K_rel slots by relation/question-conditioned evidence score.
4. Fill K_div remaining slots with diversity selection over candidate object embeddings, optionally DPP or greedy farthest-first in feature space, subject to geometric sanity constraints.
5. PoseAlign-T refines viewpoint-dependent relations before final rendering.

Supporting-context rule: unnamed objects are eligible if they satisfy a query relation, disambiguate a seed, or add a distinct evidence hypothesis. Diversity is a reserve, not the main selector, so unrelated far-away objects cannot dominate K.

Expected benefit: lower redundancy than relevance-only Top-K; lower context-loss risk on questions whose answer/support object is not semantically close to the query or spatially close to the seed.

Implementation difficulty: low-medium. DPP is CPU-feasible for ScanNet object counts; greedy diversity is an even simpler V0. No selector training required if frozen embeddings are used.

Compute estimate: selector itself negligible GPU VRAM; O(N^3) exact DPP is unnecessary at typical object counts and greedy MAP/farthest-first is practical. Main VRAM remains the <=7B 2D VLM.

Metrics: ScanQA/SQA3D QA metrics; Object Reduction Ratio; Question Entity Coverage; Supporting-Context Retention; context-loss/error rate; QA-vs-object-budget curve. Add object/category coverage and candidate redundancy as diagnostics.

Ablation: Full Scene vs Semantic Top-K vs Seed+KNN vs CAPruner endpoints vs QASER-CF relevance-only vs QASER-CF+spatial coverage vs QASER-Div feature-diversity reserve, matched at K={5,10,20}. Then +PoseAlign-T.

Risk: feature diversity is not equivalent to QA utility. DPP may preserve visually distinct but irrelevant objects. Keep relation-conditioned candidate generation before diversity and test whether diversity reserve actually improves QA. Do not claim 3DZip itself proves object-level selection.

Publication potential: moderate as a standalone selector refinement; stronger as an ablated component of QASER-CF rather than the headline novelty.

Scores (1-5; Compute Cost higher=cheaper): Novelty 3.2 standalone / 3.7 integrated; Expected Accuracy Gain 3.7; Feasibility 4.8; Compute Cost 4.9; Fit 5.0; Evidence Strength 4.8.

Target diagnostics: ORR 50-85%; QEC >=95%; SCR should exceed relevance-only selection at matched K; context-loss risk medium-low if diversity reserve is capped.

## Novelty boundary

3DZip + CoVeR materially strengthen the prior-work case that aggressive 3D evidence reduction can preserve QA, and that coverage/diversity matters. Therefore the thesis should not claim generic `diversity-aware pruning` as novelty. The defensible gap remains QA-conditioned selection of a compact set of annotated 3D objects before Abstract3D rendering, with explicit retention of unnamed supporting evidence.

## Top candidate

SAFER-QA / QASER-CF remains #1. QASER-Div is promoted as the strongest current budget-allocation refinement, not a replacement. Reason: it directly addresses the observed failure mode that answer/support objects need not be nearest to seed or highest in semantic Top-K, while preserving the constraint-first global search principle and remaining training-free/lightweight.
