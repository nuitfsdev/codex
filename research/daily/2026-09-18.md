# Daily Proposal Research — 2026-09-18

## New signal: Finder (arXiv:2609.18058, submitted 2026-09-16)
Finder is a new agentic closed-loop object-finding method for embodied grounding. Its five-stage loop is `plan -> detect -> selection plan -> select -> judge`; planning explicitly extracts a primary target plus optional supporting objects and a scoped evidence budget, while the judge can accept/continue/abort and carry structured hints into another round. It reports +15.75 points averaged 1m success rate on Habitat/HM3D object retrieval and transfers to sequential grounding/object-centric QA. Current status: arXiv preprint; project page exists. I did not verify a public code repository from primary sources today. It is not evaluated on ScanQA/SQA3D and its current detector uses SAM3, so the full method is not directly transferable under our fixed-object-annotation assumption.

### Why it matters
Finder is strong new evidence that one-shot Top-K retrieval is an unsafe abstraction when support evidence is ambiguous/missing. More importantly, it explicitly separates primary target and supporting objects, matching our seed-vs-support distinction. However, generic `closed-loop evidence gathering + supporting-object extraction` is now a stronger novelty limiter; we should not claim that mechanism alone.

## Candidate refinement: QASER-R (Recovery-Gated Support Selection)
**Research Hypothesis:** a cheap first-pass constraint-first selector can render a compact subscene; only questions whose retained evidence fails a deterministic/low-cost sufficiency check should receive a second support-expansion pass. This should reduce context-loss relative to fixed Top-K without paying iterative VLM cost on every question.

**Changed stage:** question-conditioned object selection, immediately before PoseAlign-T / Abstract3D.

**Object-selection rule:** hard-retain seed hypotheses; generate scene-wide candidates using question/relation constraints; allocate the initial object budget by relevance + non-redundancy. Do not universally gate by distance or exact noun match.

**Supporting-context rule:** unnamed supporting objects are eligible from the whole annotated scene. If the first-pass set is insufficient/ambiguous/conflicting, expand using relation endpoints, alternate referent hypotheses, and context/diversity reserve. Stop when the evidence state is sufficient or the object budget is exhausted.

**Key adaptation vs Finder:** no online detection/exploration; operate directly on provided object IDs/labels/3D boxes. Recovery means adding omitted annotated objects and/or an aligned view, not running SAM3 or exploring the environment.

**Expected benefit:** lower catastrophic context loss than fixed K while preserving high object reduction on easy questions; particularly useful when answer/support objects are neither nearest to the seed nor highest semantic matches.

**Implementation difficulty:** medium-low. V0 can use rule-based question/relation parsing + GT-box geometry + existing CAPruner/semantic candidates; recovery can initially be deterministic rather than another large agent.

**Compute:** selector/geometry negligible GPU; optional small text LLM/API for parsing; 2D VLM remains <=7B. Extra VLM cost occurs only on recovery cases. No daily GPU benchmark.

**Metrics:** ScanQA CIDEr/BLEU/METEOR/ROUGE as appropriate; SQA3D EM/accuracy; Object Reduction Ratio; Question Entity Coverage; Supporting-Context Retention; context-loss rate; recovery rate; recovered-answer rate; average rendered objects; average VLM calls.

**Ablations:** Full Scene; Semantic Top-K; Seed+KNN; CAPruner endpoints; QASER-CF fixed K; QASER-CF + diversity reserve; QASER-R with deterministic recovery; QASER-R + VLM sufficiency judge; +PoseAlign-T. Match object budgets where possible and report accuracy-vs-rendered-object curves.

**Risk:** defining Supporting-Context Retention ground truth on ScanQA/SQA3D is non-trivial; an LLM-only judge can hallucinate sufficiency; iterative recovery can erase efficiency gains. Mitigate by using answer/object-derived diagnostic labels only for evaluation where valid, and geometry/consistency checks for stopping.

**Publication potential:** medium as standalone recovery logic; high only as part of the stronger thesis claim: QA-specific retention of named + unnamed evidence before rendering under a strict object/render budget.

## Novelty boundary update
Finder plus MSSR means `iteratively request missing evidence until sufficient` is no longer a safe novelty claim by itself. The defensible distinction remains **object-level QA evidence selection before Abstract3D rendering from a fixed annotated 3D scene**, evaluated explicitly for seed retention, unnamed supporting-context retention, and object/render efficiency on ScanQA/SQA3D.

## Top candidate this week
**SAFER-QA / QASER-CF remains #1.** QASER-R becomes the preferred recovery mechanism, not a replacement headline method. It directly addresses the main failure mode of aggressive selective rendering—missing an unnamed support/answer object—while keeping the first pass training-free and cheap.
