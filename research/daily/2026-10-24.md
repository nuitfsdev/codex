## Candidate A — Discriminative Witness Budget (DWB), refinement of SAFER-QA
**Hypothesis:** Under fixed object budget K, preserve complete seed–answer–support witness bundles while reducing redundant and misleading competing candidates; this will improve ScanQA/SQA3D QA-vs-object-budget compared to independently ranked Top-K and unconstrained witness expansion. Evidence is TRANSFER motivation from video retrieval, not direct 3D validation.
**Changed stages:** question-conditioned object selection and QA utility allocator before PoseAlign-T/selected instance-mesh Abstract Renderer.
**Object rule:** parse q into explicit seed mentions, answer slot (may have unknown category), relation, frame, attributes. Frozen MiniLM/BGE-small retrieves named seeds (cache per-scene labels), retain ambiguous same-class instances. Score ALL annotated scene objects as unnamed answer/support candidates using soft geometry, relation compatibility and question-type evidence; do not use exact noun match or KNN as universal hard gate. Form witness bundles W_h (seed + potential answer + required support).
**Supporting-context rule:** retain relation endpoints, same-class disambiguators, reference frame objects, answer alternatives, and only a controlled diversity/context reserve. Preserve at least one coherent complete bundle; penalize near-duplicate bundles/distractors, but do NOT prune alternatives simply because of semantic similarity. For count/existence, detect when completeness exceeds K and report budget-insufficient; do not claim visual counting from annotation-only metadata.
**Suggested optimization (new heuristic, NOT cited method):**
max_{S subset O, |S|<=K} sum_h u_h 1[W_h subset S] - lambda sum_{a,b in S} Redundant(a,b) + mu CoverageRoles(S,q).
Here u_h is QA hypothesis confidence from non-GT annotations, not a GT answer. Tune lambda/mu only on training/validation, never test.
**Benefit:** potentially reduce context-loss and misleading-distractor rate without losing unnamed answer witness; no measured accuracy improvement.
**Difficulty:** medium; greedy budgeted bundle selection CPU, cached embeddings. Training-free V0. CPU selector adds ~0 dedicated GPU VRAM; complete VLM VRAM/latency not benchmarked. 8–16GB with 2B/4B quantized model is a feasibility target, not guaranteed.
**Data/metrics:** ScanQA val CIDEr/EM; SQA3D val EM; K={5,10,20}, M={1,2}; ORR=1-|S|/N; Question Entity Coverage; Answer-Witness Recall; Supporting-Context Retention ONLY with independent labels (otherwise proxy); Complete Witness Coverage, Distractor Density, Context-Loss Rate, latency, peak VRAM. Need held-out manually annotated 50–100 QA items with multiple valid witness sets, label reliability and inter-annotator agreement. ORR target 50–85%, QEC>=95% are NOT measured.
**Ablations:** BGE/MiniLM Top-K, Seed+KNN, FARM soft predicate, SemanticFirst-OpenSlotSoft, Role-Aware Witness Coverage, +DWB redundancy penalty, +context reserve, +PoseAlign-T; same VLM <=7B, prompts, K/M and VLM calls. Paired box-only, label+box, selected render and support-removal controls. Compare QA vs object budget and answer-witness recall vs QA (not assume monotonicity).
**Risks:** redundant-object penalty can delete essential competitors; uncertain seed disambiguation; annotation shortcuts; scene-level answer ambiguity; count K-insufficiency; context-loss HIGH at K=5, MEDIUM at K=10. **Publication:** medium only as demonstrated QA-specific integration with matched-budget gains; generic context retrieval/contrastive reranking already known.
**Scores /5:** Novelty 2.9; Expected Accuracy Gain 3.5; Feasibility 4.6; Compute Cost 4.7 (higher=cheaper); Fit 5.0; Evidence Strength 3.7. Prioritization only.

## Candidate B — SATURN-Lite Frame-Aware Soft Verification (ablation)
**Hypothesis:** Soft, frame-aware box predicates applied to already selected witness bundles reduce left/right/front/back errors relative to crisp geometry under uncertain pose, without new model training.
**Stage:** PoseAlign-T/spatial verification, not main selector. **Object rule:** reuse fixed K from SAFER-QA; no full scene rendering. **Support rule:** preserve seed + answer + frame anchor; use scene-wide scoring only BEFORE final K selection, never expand from rendered scene. **Benefit:** fewer threshold/heading errors, not demonstrated on ScanQA. **Difficulty:** low-medium CPU predicates; optional uncertainty over multiple pose hypotheses. **Compute:** no extra GPU VRAM if CPU; small CPU overhead, no VLM model scaling. **Metrics:** ScanQA/SQA3D relation subset, frame-consistency, ORR/QEC/SCR from selector, latency/VRAM. **Ablations:** crisp predicates vs soft predicates, pose-aligned vs unaligned, pose shuffle, with/without verifier, same K/M. **Risks:** frame ambiguities, box geometry inadequate for appearance/state, copying full SATURN would violate compute constraints. Context-loss unchanged by verifier. **Publication:** low standalone; evaluation/ablation value high. **Scores /5:** N1.8 G3.1 F4.8 C4.9 Fit4.7 E4.4.
