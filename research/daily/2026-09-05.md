## Candidate improvement: Relation-Conditioned Supporting-Object Expansion (RCSX)

### Research Hypothesis
For ScanQA/SQA3D, seed-object retrieval alone misses unnamed evidence. After explicit seed objects are grounded, expanding candidates according to question-conditioned relation types over a lightweight GT-box relation graph should retain supporting evidence better than KNN/radius expansion at the same object budget.

### Stage changed
OLT-QA supporting-context expansion stage, before Abstract 3D rendering; viewpoint-dependent relations are refined after PoseAlign-T.

### Object-selection rule
1. Parse the question into explicit seed/referred entities and relation/attribute intent.
2. Retrieve plausible seed instances from the GT-object lookup table using semantic labels plus optional frozen visual embeddings; retain same-class distractors until disambiguation.
3. Build lightweight pairwise relations directly from GT boxes (near, overlap/intersection where meaningful, above/below, containment/support/contact approximations, room/co-location where available).
4. Traverse only relation types compatible with the question; assign a support score from semantic compatibility + relation compatibility + geometric confidence.
5. Select support objects under a fixed object budget; do not render the rest of the scene.
6. After PoseAlign-T, recompute left/right/front/behind and prune inconsistent directional candidates.

### Supporting-context rule
Seed objects are hard-retained. Supporting objects may be unnamed in the question and are admitted through relation-compatible 1-hop expansion; optional 2-hop expansion is allowed only when the first hop is high-confidence. This explicitly differs from exact noun match and unconstrained KNN.

### Expected benefit
Higher Supporting-Context Retention at the same Object Reduction Ratio, especially for relational questions whose answer object is not named in the question. Could reduce abstract-scene clutter without sacrificing QA evidence.

### Difficulty / compute
- Implementation difficulty: medium (3/5).
- No new detector/segmenter and no 3D model training.
- Geometry graph construction is cheap CPU work from GT boxes.
- Optional frozen CLIP/SigLIP features can be cached per object; estimated incremental VRAM is small relative to the <=7B VLM backbone.
- Avoid reproducing ReasoningGraph's full Hydra/ROS pipeline.

### Evaluation
Primary: ScanQA/SQA3D QA metrics plus average rendered-object count and Object Reduction Ratio.
Diagnostic: Question Entity Coverage, Supporting-Context Retention via manually/heuristically curated failure subsets where answer/support objects are not explicit nouns, relation-type breakdown, context-loss rate.

### Required ablations
- Full scene.
- Seed only.
- Seed + KNN.
- Seed + radius.
- Seed + relation-conditioned 1-hop support.
- + optional 2-hop support.
- + PoseAlign-T directional refinement.
- Fixed object-budget sweep to compare retention rather than allowing RCSX to win by keeping more objects.

### Risks
- ScanQA does not provide a complete minimal supporting-object ground truth, so Supporting-Context Retention cannot be treated as a perfect supervised metric.
- Box-derived relations such as support/contact can be noisy without meshes.
- Relation graph + task-relevant retrieval already has prior art; novelty cannot be claimed for scene-graph retrieval itself. The research contribution, if any, must be QA-specific support retention under an abstract-rendering budget and its interaction with PoseAlign-T.
