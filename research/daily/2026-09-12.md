## 1. AgentGrounder code inspection: important limitation for object selection
Paper: AgentGrounder: Zero-Shot 3D Visual Pointcloud Grounding using Multimodal Language Models (arXiv:2605.25901, 2026-05-25). Public code: `be2rlab/AgentGrounder`.

### What the paper establishes
AgentGrounder is zero-shot and builds an Object Lookup Table containing instance IDs, labels and 3D boxes, then lets a tool-using agent retrieve candidates, apply geometric tools and render only when additional visual evidence is needed. This strongly supports the general thesis principle that full-scene prompting/rendering is unnecessary.

### What the official code actually does
The public `query_relevant_objects` tool performs vector-store semantic retrieval with a hard `k=5` and score threshold `0.1` before spatial reasoning. Therefore its default candidate-retrieval path can discard a correct answer/support object that is semantically weak with respect to the question. The code also exposes exact-label lookup, pairwise distance, farthest-object and other geometric tools, but these are agent-invoked after or alongside retrieval rather than a guarantee of global relation-conditioned candidate coverage.

This directly answers the current concern: answer/support objects are not guaranteed to be nearest to or semantically similar to a named seed. A method whose first hard bottleneck is semantic Top-K is unsafe for ScanQA/SQA3D support selection.

## Candidate improvement: CRG — Constraint-first Relation-Guided Global Selection
### Research Hypothesis
For QA, relation intent should determine the candidate search operator before any hard semantic Top-K truncation. Geometry should verify relation constraints over the relevant global object set rather than define a generic local neighborhood.

### Stage changed
`question-conditioned object selection` before PoseAlign-T / Abstract Renderer.

### Object-selection rule
1. Parse explicit seed/referred entities and relation/question type.
2. Hard-retain all plausible seed instances.
3. Select search operator by relation intent:
   - `next to / beside`: evaluate horizontal/local adjacency across all objects;
   - `on / under`: vertical ordering + XY footprint overlap/support;
   - `inside / contains`: box containment/intersection;
   - `left/right/front/behind`: delay hard pruning until PoseAlign-T, then evaluate aligned coordinates;
   - attribute QA (`color/material`): first resolve referred object candidates, do not search answer label semantically;
   - room/global/functional QA: permit scene-wide semantic/graph candidates; do not impose radius/KNN.
4. Only after constraint-compatible candidate generation, apply semantic relevance/diversity to meet the object budget.

### Supporting-context rule
Supporting objects may be unnamed and may be far from the seed. Keep them if they satisfy a relation/graph constraint or are needed to disambiguate among plausible candidates. Distance is a relation-specific feature, not a universal gate.

### Expected benefit
Higher answer/support recall at the same object budget than semantic-TopK-first or KNN-first selectors; especially helpful when answer categories are absent from the question.

### Difficulty / compute
Implementation difficulty: medium-low with GT boxes. No training required. Geometry is CPU-cheap; optional frozen text embeddings are negligible. Main VRAM remains the <=7B VLM used downstream.

### Metrics
ScanQA/SQA3D QA accuracy / EM@1 / CIDEr as appropriate; Object Reduction Ratio; Question Entity Coverage; candidate recall proxy; Context Benefit Rate; Support Ablation Sensitivity; QA-vs-object-budget curve. Supporting-Context Retention remains proxy-only unless a support annotation protocol is introduced.

### Core ablation
`Full Scene` vs `Semantic Top-5 first (AgentGrounder-style)` vs `Seed+KNN` vs `Seed+radius` vs `Constraint-first global relation filtering` vs `Constraint-first + semantic/diversity budget` vs `+PoseAlign-T`.

### Risks
Question parser errors; relation rules can be brittle; open-ended/non-spatial questions may require fallback semantic/global search; box-only geometry cannot verify fine material/appearance evidence.

### Scores (1-5)
Novelty 3.2 standalone / 3.6 inside QASER; Expected Accuracy Gain 3.8; Feasibility 4.7; Compute Cost 4.9 (higher=cheaper); Fit 5.0; Evidence Strength 4.6.
Targets to test, not claims: Object Reduction Ratio 50-85%; Question Entity Coverage >=95%; Supporting-Context Retention unknown/proxy; context-loss risk medium-low relative to semantic-TopK-first.

## 2. IVSGround status update
`Where to Look Matters: Learning Influential Views for VLM-based 3D Visual Grounding` (arXiv:2609.04741, submitted 2026-09-04) is marked accepted to ECCV 2026. It trains a lightweight query-conditioned view selector from reasoning-VLM feedback, then uses a frozen reasoning VLM for comparative grounding on ScanRefer/NR3D.

Impact on thesis: strengthens the novelty boundary around learned question-conditioned view selection. Keep view selection secondary/ablation; main novelty should remain object/subscene evidence selection. The trained selector also makes it less aligned with a strictly training-free main method.

## Saturday weekly synthesis
The week's strongest conclusion is now sharper than `seed + nearby supports`:

`question -> seed hypotheses -> relation/question-type parser -> constraint-first candidate generation over the appropriate global set -> QA-support budget allocation -> PoseAlign-T directional refinement -> selective Abstract-3D rendering -> <=7B VLM`

Do not use generic KNN/radius as the main selector. Do not hard-truncate semantic Top-K before relation-aware search. Use CAPruner / AgentGrounder / PruneGround as baselines or evidence sources, not as proof that their candidate bottlenecks preserve QA evidence.

## Top candidate of the week
**SAFER-QA / QASER with CRG (Constraint-first Relation-Guided selection)** remains #1.

Reason: the defensible contribution is increasingly specific: preserve a minimal set of QA-useful seed + unnamed supporting objects under a render budget, and generate candidates according to the question's relation semantics rather than assuming semantic similarity or geometric proximity. This directly addresses the failure mode observed in semantic Top-K and KNN-style selection while staying training-free, cheap, compatible with ScanQA/SQA3D GT boxes, PoseAlign-T and selective Abstract-3D rendering.
