## Fresh update retained today

### Seeing Once is Enough? Online Geometry-Aware Token Pruning for 3D Question Answering
- arXiv: 2607.04079, submitted 2026-07-05.
- Status: Published at the First Workshop on Efficient Spatial Reasoning at ICLR 2026; not a main-track conference paper.
- Training: none; plug-and-play inference-time pruning.
- Backbones tested: Qwen2.5-VL-7B and Qwen3-VL-8B.
- Benchmarks: ScanQA, SQA3D, OpenEQA-HM3D.
- Method: project posed RGB-D frames into a shared voxel space, identify regions already observed in prior frames, and prune image tokens corresponding to geometric overlap before VLM inference.
- Reported results: up to ~50% token reduction. On ScanQA with Qwen2.5-VL-7B, EM 24.1 -> 25.1 and CIDEr 65.6 -> 69.3 while token count falls 37.1M -> 32.6M in the online uniform setting. On SQA3D, EM 46.5 -> 47.3 with token reduction 28.0M -> 24.1M.
- Code status: paper states code will be released; no verified official public repository found in today's search.

### Transfer candidate: Post-selection Geometry-Aware Visual Token Pruning
Research Hypothesis: After question-conditioned object/subscene selection and PoseAlign-T, abstract multi-view rendering still contains cross-view redundancy. Geometry-aware token pruning can reduce redundant visual evidence without removing selected objects, improving the QA/compute trade-off.

Stage changed: after selected-subscene multi-view rendering, before the 2D VLM vision-token stream.

Object-selection rule: unchanged; use OLT-QA or another subscene selector first. This candidate is explicitly not a replacement for object selection.

Supporting-context rule: hard-preserve all selected seed/support objects at object level. Token pruning may remove only patches whose projected 3D support is already represented by another retained view; never use semantic irrelevance alone to prune supporting objects.

Expected benefit: lower visual-token count and reduced multi-view redundancy; possible small QA gain from reduced attention dilution.

Implementation difficulty: medium. Needs RGB-D/depth and pose for each rendered or source view plus access to the VLM visual-token masking path.

Compute estimate: no training; Qwen2.5-VL-7B was demonstrated directly. A 7B backbone is within the thesis scope; published experiments used standard inference only. Exact VRAM was not reported in the paper and should not be invented.

Data/metrics: ScanQA/SQA3D EM/CIDEr; total visual tokens; latency; peak VRAM; per-question number of retained views/tokens. For the object-selection track also keep Object Reduction Ratio, Question Entity Coverage and Supporting-Context Retention from the upstream selector.

Ablations:
1. Full scene + fixed multi-view.
2. Selected subscene + fixed multi-view.
3. Selected subscene + view selection.
4. Selected subscene + geometry-aware token pruning.
5. Selected subscene + view selection + geometry-aware token pruning.
6. Pruning threshold sweep and protected-object-mask ablation.

Risk: this is token-level redundancy pruning, not question-conditioned object/subscene selection. Using it as the thesis novelty would shift the project away from the intended research track. Treat it as a secondary efficiency module/ablation.

Scores (1-5): Novelty 2.0 standalone / 2.5 as pipeline integration; Expected Accuracy Gain 3.0; Feasibility 4.0; Compute Cost 4.5 (higher=cheaper); Fit 4.0; Evidence Strength 4.5.
Object-selection metrics: Object Reduction Ratio = unchanged from upstream selector; Question Entity Coverage = unchanged if protected masks are used; Supporting-Context Retention = should remain unchanged at object level; context-loss risk low-medium at token level if pruning threshold is too aggressive.
Publication potential: secondary module only; not enough as the main thesis novelty because geometry-aware token pruning is already the paper's core contribution.

## Evidence note: SmartMage
SmartMage (arXiv 2608.05137, 2026-08-05) dynamically routes visual/geometric modalities according to query semantics and reports strong 3D scene-understanding results including ScanQA. However, it is a trained unified MLLM with adaptive routing/gating, which violates the thesis preference for training-free/inference-only methods and is not an object/subscene selector. It is useful as evidence that query-dependent evidence type selection matters, but not as a direct implementation candidate.
