# Daily Proposal Research — 2026-09-24

## Fresh scan result
No new 2026-09-23/24 paper was found that directly displaces the current object-selection shortlist. The strongest newly incorporated evidence is **SceneBench: A Hierarchical Benchmark for Vision-Language Understanding of 3D Scenes** (arXiv:2609.16233, submitted 2026-09-14; current status: arXiv preprint).

## Why SceneBench matters
SceneBench contains 966 photorealistic 3D scenes, >183K hierarchical nodes with textual descriptions and 3D boxes, and 33,524 QA pairs. It explicitly organizes evidence as scene -> room -> functional area -> object group -> object and includes existence, counting/size/distance/direction, and grounded multi-step QRA tasks.

This is relevant to QASER because its grounded reasoning examples require evidence acquisition across levels: scene overview -> area -> target -> adjacent/support objects -> fine details -> inference. This provides stronger evidence that a selector restricted to exact question nouns, seed-local KNN, or flat object relevance can lose unnamed support/context needed by compositional QA.

## Candidate improvement: H-QASER (Hierarchical Support Expansion)
**Research Hypothesis:** a cheap hierarchy/context prior can improve supporting-object retention under the same object budget by first locating a likely room/functional group and then allocating object slots within and across relevant groups, rather than ranking all objects independently.

**Changed stage:** question-conditioned object/subscene selection before PoseAlign-T and Abstract3D rendering.

**Object-selection rule:** hard-retain explicit seeds; generate relation-compatible candidates scene-wide; optionally infer coarse room/functional-group relevance; allocate most K to QA evidence within relevant groups while preserving a small cross-group/context reserve. Geometry is a relation-specific verifier, not a universal proximity gate.

**Supporting-context rule:** unnamed objects are retained when they complete a relation path, disambiguate seed instances, are evidence for the requested attribute/relation, or belong to a functional/object group implicated by the question. Do not require exact noun match.

**Expected benefit:** better retention for compositional/global questions and lower context-loss than flat SemanticTopK/KNN at matched K.

**Implementation difficulty:** medium. ScanQA/SQA3D do not natively provide SceneBench-style functional hierarchy, so H-QASER should be a secondary/optional module, not the core method. A cheap hierarchy can be approximated from ScanNet room/scene membership, object clusters, or LLM-generated group labels, but this introduces noise.

**Training/compute:** training-free candidate; CPU geometry/grouping plus optional small LLM/VLM query. No daily GPU benchmark. VLM remains <=7B. Incremental VRAM is negligible if hierarchy is precomputed; inference cost is one lightweight parsing/group-relevance pass if not cached.

**Metrics:** downstream ScanQA/SQA3D QA; Object Reduction Ratio; Question Entity Coverage; proxy Supporting-Context Retention; Context Benefit Rate; Support Ablation Sensitivity; QA-vs-object-budget. SceneBench can be used later as an auxiliary stress-test because it has explicit hierarchical grounding and 3D boxes, but it should not replace ScanQA/SQA3D as the thesis primary benchmarks.

**Ablation:** Flat QASER vs H-QASER at K={5,10,20}; remove hierarchy prior; remove cross-group reserve; exact-noun-only vs seed+unnamed-support; before/after PoseAlign-T for directional questions.

**Risks:** hierarchy inference is not native to ScanQA/SQA3D; noisy functional groups can over-prune; SceneBench's Gaussian-splatting input differs from the current ScanNet/abstract-render pipeline. Avoid making hierarchy generation a new heavy contribution.

**Publication potential:** moderate as a refinement only if matched-budget experiments show improved compositional/global QA and support retention. Hierarchical scene reasoning itself is not novel.

**Scores (1-5):** Novelty 2.8 standalone / 3.4 integrated; Expected Accuracy Gain 3.7; Feasibility 4.0; Compute Cost 4.7 (higher=cheaper); Fit 4.6; Evidence Strength 4.6.

**Object-selection targets:** ORR 50-85%; QEC >=95%; Supporting-Context Retention remains proxy-only on ScanQA/SQA3D; context-loss risk medium, potentially lower than flat selection for multi-step questions.

## Novelty boundary update
SceneBench makes it harder to claim generic hierarchical context or multi-level reasoning as novelty. The defensible thesis claim remains QA-specific pre-render retention of named seeds plus unnamed supporting objects under a strict object/render budget. Hierarchy should be treated as a support prior/ablation, not the headline contribution.

**SAFER-QA / QASER-Utility remains #1.** H-QASER is a refinement, not a replacement. The strongest reason is unchanged: the most testable remaining gap is whether QA-specific support retention yields a better QA-vs-object-budget frontier than grounding-oriented pruning and question-independent object coverage on ScanQA/SQA3D.
