## Newly listed: R4DGS / ReferGaussian
- Paper https://arxiv.org/abs/2610.30326 ; project https://chenbangpu.github.io/R4DGS/ ; official code https://github.com/chenbangpu/R4DGS ; data https://huggingface.co/datasets/LiYacheng/r4d-bench-qa
- Submission 2026-10-21; authors Bangpu Chen et al.; venue ACM Multimedia 2026 (paper/project claim, DOI 10.1145/3767308.3836021).
- EntityBank + MLLM query planner handles identity, temporal, relational, cardinality, exclusion and **zero-target** constraints. Dataset: 12 dynamic scenes, 89 queries (36 temporal, 29 multi-target/reasoning, 24 zero-target); project reports 76.5 Acc / 34.4 vIoU vs 58.4 / 32.1 for 4D LangSplat on its benchmark. These are NOT ScanQA/SQA3D scores.
- Official repo includes scripts/configs/tests and training of 4D Gaussian scene models; no task-specific referring fine-tuning is required *after* frozen 4DGS preparation, but the complete workflow is NOT training-free and requires CUDA 12.1, NVIDIA GPU and COLMAP. VRAM/time for complete setup not established. Dataset files are published, but HF viewer currently errors with a schema cast; download/scripts require validation.
- Transfer only structured query constraints, especially null/exclusion/cardinality logic. Do NOT transfer 4DGS, mask discovery, segmentation, dynamic training or 8B+ backbone as core novelty. Main thesis remains fixed ScanNet annotations and pre-render object pruning.

## Important prior-work audit: Scene-Q
- IROS 2026; Juno Kim et al.; project https://teamrobi.github.io/projects/scene-q/ ; official code https://github.com/teamROBI/Scene-Q (MIT).
- Encoder confidence (temperature, top-1 probability, margin, normalized entropy) routes ambiguous instance classification to Qwen2.5-VL-7B and leaves confident cases on cheap retrieval. - Original perception pipeline includes mask/segmentation refinement and multi-view RGB; out of scope. Adapt confidence-gated re-ranking as a BASELINE only, not a new selector novelty. Fit for cheap frozen semantic seed disambiguation, not proof of unnamed supporting-object retrieval.

## Important evaluation audit: Beacon3D
- CVPR 2025; Jiangyong Huang et al.; project https://beacon-3d.github.io/ ; official code/data https://github.com/beacon-3d/Beacon3D (Apache-2.0).
- 30 curated scenes from ScanNet, 3RScan, MultiScan; >800 target objects; grounding chains and grounding-QA chains with object IDs; three question variants per object. Tests coherence between correct grounding and correct QA, and language robustness. Evaluator contains an LLM scoring path/API requirement; a locally reproducible subset should use deterministic EM or own clearly documented rubric.
- CRITICAL: target-object and grounding-QA chain annotations are **not** complete independent annotations of all unnamed supporting/context objects. They can validate seed/target retention and shortcut diagnosis, NOT full SCR ground truth. For SCR, annotate a held-out small sample with multiple valid witness sets and inter-annotator agreement. Keep Beacon3D as external diagnostic, not a substitute for ScanQA/SQA3D.

## Candidate A (new refinement): QASER-NullSafe-OpenSlot
Research hypothesis: adding explicit no-target/exclusion/cardinality handling to semantic-first, role-aware *scene-wide* unnamed witness retrieval reduces false-positive evidence and unsupported QA answers at fixed pre-render object budget.
Stage: typed question parsing -> scene-wide answer/support candidate scoring -> witness allocation, before PoseAlign-T and selected-instance-mesh Abstract3D.
Object-selection rule: parse named seed(s), open answer slot, relation, negation/exclusion, cardinality and reference frame. Retrieve seeds with frozen BGE-small/MiniLM and synonyms; score every fixed annotated object as an unnamed answer/support candidate via soft relation/attribute/geometry compatibility; no exact-noun or KNN universal hard gate. Keep K objects max. An empty high-confidence answer candidate set is a separate symbolic state, not an invitation to hallucinate an answer.
Supporting-context rule: retain relation endpoints, disambiguating same-class seeds, competing candidates and reference-frame objects; for negative/existence/count queries, mark whether exhaustive annotation-level checking is possible and whether required visual evidence exceeds K. Do not claim box-only proof for color/state/affordance; route uncertain questions to normal selected-render VLM or explicit uncertainty.
Suggested score: s(a|q,s)=w_sem*s_sem+w_rel*s_rel+w_geo*s_geo; weights/threshold tuned only on validation. Null flag is allowed only when exhaustive, well-defined symbolic predicate over fixed annotations is satisfied; track this as metadata-oracle control.
Expected benefit: fewer unsupported affirmative/negative responses and more robust open-slot evidence. Expected QA gain unverified; most ScanQA questions are positive, so effect on aggregate CIDEr may be small.
Difficulty medium; V0 training-free CPU semantic encoder+box operations, cache object embeddings. Additional selector GPU VRAM ~0 if CPU; total 2B/4B quantized VLM peak memory unmeasured and depends on M/resolution. Start 8-16GB as feasibility target, not guaranteed.
Data/metrics: ScanQA val, SQA3D val, Beacon3D existence subset (diagnostic), controlled negative/exclusion probes derived from fixed annotations on held-out scenes; separate metadata-only vs render-dependent results. ScanQA CIDEr/EM, SQA3D EM, ORR=1-|S|/N, QEC, Answer-Witness Recall, SCR (proxy until independent GT), Null-Target Precision/Recall, False-Evidence Rate, Context-Loss Rate, latency, peak VRAM.
Ablations: BGE TopK, OpenSlotSoft, Role-Aware Witness Coverage, +null/exclusion handling, +confidence-gated reranking; K={5,10,20}, M={1,2}; same VLM/prompt/renderer/calls. Evaluate with and without metadata-only null route; test label+box-only, selected renders, and supporting-object removal.
Risks: incomplete object annotations, ambiguous negation, relations not expressible by boxes, overly aggressive null decisions, budget insufficiency for counting. Context-loss HIGH at K=5; publication LOW standalone / MEDIUM as a measurable QA-specific refinement, only with matched-budget gains.
Scores (/5; compute higher=cheaper): Novelty 2.7, Expected Accuracy Gain 3.0, Feasibility 4.6, Compute Cost 4.8, Fit 4.9, Evidence Strength 3.5. These are PRIORITIZATION scores, not benchmark evidence.

## Candidate B (evaluation refinement): ChainGuard-GroundingQA Audit
Hypothesis: jointly measuring target grounding/retention and answer correctness, including paraphrases, can distinguish visual-grounding improvements from language/annotation shortcuts.
Stage: evaluation only; no selector or renderer change.
Object selection/support rule: freeze selected S from SAFER-QA; record named target coverage and any independently annotated supporting witness sets. Beacon3D target chains are NOT support labels.
Expected benefit: stronger causal/grounding evidence, not necessarily direct QA gain. Training-free; low difficulty; additional VLM calls to evaluate QA; no additional per-call VRAM. Metrics: target retention, object-centric all-three-correct, grounding-QA coherence, support-removal delta, label+box-only vs render gap, ORR/QEC/SCR. Risks: small external benchmark, domain shift, evaluator API, lack of support GT. Publication LOW standalone, MEDIUM as rigorous evaluation.
Scores (/5): Novelty 2.0, Expected Accuracy Gain 1.0, Feasibility 4.6, Compute Cost 4.2, Fit 4.9, Evidence Strength 4.7.
