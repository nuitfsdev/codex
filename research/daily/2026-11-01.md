## Paper 1 — ClueTracer (important newly audited update; NOT a new Nov paper)
*ClueTracer: Question-to-Vision Clue Tracing for Training-Free Hallucination Suppression in Multimodal Reasoning*, Gongli Xi et al. arXiv https://arxiv.org/abs/2602.02004 (v1 2 Feb; **v2 28 Oct 2026**); **EMNLP 2026 MAIN**, official proceedings https://aclanthology.org/2026.emnlp-main.1556/ (DOI 10.18653/2026.emnlp-main.1556); arXiv authors label Oral, official anthology confirms main paper, not necessarily oral. Mechanism: training-free question -> generated-output -> visual-token attention tracing, evidence-region construction, optional crop re-inference; ClueRecall diagnostic. Does **NOT** retrieve physical objects from fixed 3D boxes before rendering; is a POST-render clue-tracing/attention intervention, strong prior art for question-grounded evidence filtering.

**3DSRBench appendix Table 7 (important):** Ocean-R1 37.66% -> 40.06% (+2.40 pp); ORSTA 43.44% -> 45.14% (+1.70 pp); MM-Eureka 56.25% -> 59.24% (+2.99 pp). These are **2D spatial reasoning** results on authors' reasoning backbones, **NOT ScanQA/SQA3D** and not a guaranteed gain for Qwen2.5-VL-3B. Source https://arxiv.org/html/2602.02004v2 §D.3. Authors also report general reasoning 1.21x, not 1.21 percentage points. Original deployment Table 12: 7B model on one RTX 3090 reported as '20G', latency 0.91h/1000 items offline vs 1.36h/1000 with stage1 length 50; NOT verified T4/4-bit peak VRAM. Code link in arXiv HTML points to https://github.com/Lrbomchz/emnlp_cluereacer and returned 404 at check time; official runnable code NOT verified (do not claim released). ## Candidate A — Selected-Render Clue Sufficiency Audit (SRC-SA; SECONDARY, not main)
**Research Hypothesis:** with the SAME pre-render selected set S and VLM, identifying whether rendered visual evidence actually supports seed–answer–support witness relations can reveal and possibly reduce hallucinated ScanQA/SQA3D answers; any downstream gain requires controlled measurement.
**Changed stages:** after selected-mesh rendering: evidence verification / structured reasoning, optionally second inference. **Object-selection rule:** freeze SAFER-QA S, |S|<=K; named seeds via semantic synonyms, scene-wide unnamed answer/support via soft relations, no full-scene rendering. **Supporting-context rule:** keep answer endpoints, relation bridges, reference anchors, same-class disambiguators selected by SAFER-QA; do not remove them on low attention alone; distinguish not-visible-in-view vs not-in-scene. **Implementation V0:** no attention instrumentation; compare selected render + ID overlay vs label-only/box-only vs support-object masking and manual evidence audit. V1 optional Q->output->vision attention on selected renders only if compatible code and model attention hooks available; label-only controls. **Expected benefit:** stronger evidence fidelity and hallucination diagnostics; accuracy gain uncertain. **Difficulty:** medium/high for attention hooks, low for V0. **Training:** none. **Compute:** V0 CPU for metadata + extra sequential VLM calls for controls; V1 may require output_attentions and longer KV/attention memory; author used 7B RTX3090, T4 16GB peak VRAM unknown, do NOT promise fits. **Data:** ScanQA/SQA3D val; 3DSRBench as optional 2D diagnostic, not replacement. **Metrics:** QA EM/CIDEr, ORR, QEC, Answer-Witness Recall, independent-GT SCR or clearly marked proxy, Context-Loss Rate, clue localization on projected selected-object masks, evidence-supported answer rate, latency, peak VRAM. **Ablations:** same K=10 M=1 VLM/prompt; no verifier vs support removal vs random mask vs optional attention-guided crop; matched VLM-call/image-token budget or report extra cost separately; K=5/20 and M=2 later. **Risks:** attention != faithful causal attribution, extra inference violates matched-budget comparison, masking alters occlusion, attention hooks/quantization may exceed T4, context-loss HIGH at K=5 and for counting. **Publication:** LOW standalone, MEDIUM only as validation strengthening SAFER-QA; not primary novelty. **Scores /5:** Novelty 1.7, Expected Gain 2.7, Feasibility 3.4, Compute 3.1 (higher=cheaper), Fit 4.4, Evidence 4.6 (prior evidence, not ScanQA candidate proof).

## Candidate B — Counterfactual Target/Frame Binding Audit (CTFBA; EVALUATION ONLY)
**Research Hypothesis:** correct QA answers should depend on the correct named seed instance and viewpoint frame; switching an ambiguous seed ID or perturbing reference heading in paired valid cases should reveal semantic/pose shortcuts.
**Changed stages:** evaluation of pre-render selector, PoseAlign-T, spatial verification. **Object-selection rule:** run normal fixed-box named-seed + unnamed-answer/support selector on the original question; for counterfactual, change a legitimate referring expression / target constraint and rerun selector with same K; only selected objects rendered. **Supporting-context rule:** retain bridges/reference anchors in both paired cases and independently annotate expected answer change; do not call changed object GT 'support' without annotation. **Expected benefit:** error attribution and stronger thesis validity, not guaranteed QA gain. **Difficulty:** medium, requires curated pairs. **Training:** none. **Compute:** CPU box geometry + paired VLM inference on <=7B, 8–16GB 4-bit is an UNMEASURED planning target. **Data:** 50–100 curated ScanQA/SQA3D val pairs; BEHAVIOR-Spatial only inspiration. **Metrics:** paired answer consistency, seed-binding accuracy, ORR/QEC/AWR/SCR where independent GT, context-loss, QA EM/CIDEr, latency/VRAM. **Ablation:** correct vs swapped seed, correct vs changed heading only for heading-dependent questions, label-only vs selected render, K=5/10/20. **Risks:** invalid counterfactual GT, pose visibility confounding, labels as shortcut; HIGH context-loss at K=5. **Publication:** LOW standalone. **Scores:** N1.5 Gain1.5 F4.2 C4.3 Fit4.7 Evidence4.0.
