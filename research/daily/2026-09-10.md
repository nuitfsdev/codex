## CAPruner source-level findings
Paper: Zhou et al., **CAPruner: Conceptual-Adjacent Scene Graph Pruner for Enhancing 3D Spatial Reasoning of Large Language Models**, ACL 2026 Long Papers, pp. 555–567. Official code: `fz-zsl/CAPruner`.

### What it actually does
- CAPruner prunes **scene-graph edges/relations**, not objects directly.
- Relation importance combines a fuzzy/category relevance signal from the query with spatial proximity.
- The official `SoftCategNodeVal` is still lexical/category-map based: ScanNet raw/category/NYU synonym groups are matched against the utterance. It is not a general semantic encoder or LLM selector.
- The pruner is **trained**, not training-free. Official config uses ScanRefer + ScanQA + Multi3DRefer, batch size 16, max 150 objects, 50 epochs, hidden dim 32.
- Official pipeline supports GT or Mask3D boxes and provides pretrained/inference outputs, so using the released checkpoint is lightweight at inference but is not methodologically training-free.

### Consequence for the thesis
CAPruner should not be the proposed selector unchanged. It is best treated as a **relation-aware prior / baseline** inside QASER:

`GT boxes -> seed resolution -> CAPruner-style relation graph pruning -> convert retained incident-edge support into candidate objects -> QA-utility-aware budget allocator -> PoseAlign-T -> Abstract render`

The thesis contribution must remain downstream of generic graph pruning: which retained/expanded objects are actually useful for open-ended QA under a strict rendering budget.

## Candidate: CAP-QASER transfer
**Research hypothesis:** CAPruner-style relation preservation provides a stronger support-candidate pool than KNN/radius alone, but open-ended QA requires an additional object-budget allocation rule because edge relevance is not equivalent to answer-evidence utility.

**Stage changed:** question-conditioned object/subscene selection.

**Object-selection rule:** hard-retain resolved seed instances; build a lightweight graph from GT boxes; use CAPruner checkpoint/output or a training-free approximation of its conceptual-adjacent score to rank incident edges; convert endpoints of top edges into support candidates; then select K support objects with QASER relation/diversity allocation.

**Supporting-context rule:** supporting objects may be unmentioned; require either (a) a high-ranked relation path to a seed, or (b) a reserved spatial-diversity slot. Do not require exact noun match for supporting objects.

**Expected benefit:** stronger relational context retention than seed-only/KNN while still avoiding full-scene rendering.

**Implementation difficulty:** 2.5/5 using released CAPruner inference outputs; 3.5/5 if reproducing training/data preprocessing. Graph-to-object conversion itself is simple.

**Training/compute:** CAPruner original method trains a small 32-d model for 50 epochs; exact VRAM is not reported in the config/source inspected today. Inference with official checkpoint should be cheap relative to the <=7B VLM. For the thesis, prefer released checkpoint or a training-free approximation rather than retraining unless necessary.

**Data/metrics:** ScanQA primary; SQA3D transfer must be implemented/evaluated separately because the official config explicitly lists ScanRefer, ScanQA, Multi3DRefer, not SQA3D. Measure downstream QA, Object Reduction Ratio, Question Entity Coverage, object-budget-vs-QA, Context Benefit Rate, Support Ablation Sensitivity; Supporting-Context Retention remains proxy-only without explicit support GT.

**Ablation:** Full Scene vs Seed-only vs Seed+KNN vs Seed+Radius vs CAPruner-edge-endpoint objects vs CAPruner+QASER budget allocation vs training-free CAP-style approximation+QASER vs +PoseAlign-T. All object-selection variants must be matched by retained-object budget.

**Risks:** (1) CAPruner is trained and can leak dataset-specific priors into a nominally training-free pipeline; (2) lexical/category fuzzy matching can miss paraphrases or implicit relations; (3) pruning edges does not guarantee minimal useful object subset; (4) official SQA3D support is not present in the inspected config; (5) retained graph connectivity can preserve grounding anchors but not necessarily QA evidence.

**Publication potential:** moderate as a baseline/transfer component, low as standalone novelty. Stronger only if QASER demonstrably converts relation-pruning outputs into a better QA-specific minimal subscene than CAPruner endpoints alone at equal object budget.

## Novelty boundary update
Do not claim fuzzy semantic + spatial-proximity scene-graph pruning, relation-aware task-specific pruning, or query-specific graph compression as novel. CAPruner already establishes those at ACL 2026. The defensible gap remains **QA-specific object evidence retention under a strict abstract-render budget**, especially for supporting objects not recoverable purely from query-graph anchors.

## Top candidate of the week
**SAFER-QA / QASER remains #1.** Today strengthens the baseline set rather than replacing it.
