# Daily Proposal Research — 2026-09-09

## Material update: PruneGround directly narrows the unnamed-support novelty gap

**Paper:** PruneGround: Plug-and-play Spatial Pruning for 3D Visual Grounding (arXiv:2606.31148, 2026-06-30; current status verified as arXiv/CoRR preprint). **Code:** public MIT repo `leduckhai/PruneGround`. **Benchmarks:** ScanRefer, Nr3D, Sr3D. **Pruning VLM:** frozen Qwen2.5-VL-3B-Instruct by default. The full LLM-Grounder is not training-free: it repurposes/fine-tunes a detection-pretrained spatial LLM; therefore only LGSP/MCDR are transferable to the thesis constraints.

### Why this matters for SAFER-QA
PruneGround does more than referenced-object pruning. Its released MCDR output schema explicitly contains `anchors_visual`: anchors detected in side views but absent from the original language description. This is the closest prior found so far to the thesis idea of retaining/adding objects that are not explicitly named in the question.

However, the task boundary remains important: PruneGround uses those visually inferred anchors to reformulate a referring expression for **target grounding**. It does not optimize a minimal object subset for **open-ended ScanQA/SQA3D answer evidence**, does not report QA-vs-object-budget curves, and does not distinguish answer-support utility under fixed rendering budgets. Therefore generic `unnamed object expansion` can no longer be claimed as novel; the defensible gap is **QA-utility-aware unnamed support selection under a strict object/render budget**.

### Evidence from PruneGround
- Language-Guided Spatial Pruning (LGSP) uses a frozen VLM to restrict the grounding region.
- MCDR decomposes target-anchor relations and can add visual anchors absent from the description.
- Reported target recall for pruning is ~94.7% with four oblique RGB+depth views.
- Average candidates reportedly fall from 5.72 to 1.62 on ScanRefer Multiple and 2.43 to 1.28 on Sr3D Hard.
- Reported grounding results: 63.8/56.1 Acc@0.25/0.5 ScanRefer overall, 75.1 Nr3D overall, 81.5 Sr3D overall.

## Candidate refinement: QASER — QA-Specific Evidence Retention

**Research hypothesis:** among objects not mentioned in the question, only a small subset has positive downstream QA utility. Selecting these objects using relation compatibility + geometry diversity + optional co-visibility, under a matched object budget, can preserve or improve ScanQA/SQA3D accuracy better than grounding-oriented visual-anchor discovery.

**Stage changed:** `seed retrieval -> support candidate generation -> fixed-budget evidence allocation` before PoseAlign-T and Abstract Renderer.

**Object-selection rule:** hard-retain plausible seed entities; generate unnamed candidates using cheap box relations (near/support/contain/above-below/overlap) plus optional co-visibility; allocate K support slots by relation score and geometric diversity. Do not use exact noun match as the support criterion.

**Supporting-context rule:** support candidates may be absent from the question. Unlike PruneGround/MCDR, candidate utility is defined by downstream QA preservation/gain rather than whether the object is a good grounding anchor.

**Expected benefit:** less clutter than full-scene rendering while retaining answer-bearing context that Seed-only/GraFT-style referenced-object rendering can miss.

**Implementation difficulty:** low-medium; all core selection features can be computed from fixed GT boxes and existing camera metadata. No new detector/segmenter and no daily GPU benchmark required.

**Compute/VRAM:** selector negligible; main cost remains <=7B 2D VLM. Optional Qwen2.5-VL-3B parsing can fit the preferred compute envelope, but deterministic geometry should be the default where possible.

**Metrics:** ScanQA/SQA3D QA; Object Reduction Ratio; Question Entity Coverage; object-budget-vs-QA curve; Context Benefit Rate; Support Ablation Sensitivity. Supporting-Context Retention remains proxy-only without explicit support GT.

**Critical ablation:** Full Scene vs Seed-only vs PruneGround-inspired visual-anchor expansion vs Seed+KNN vs Seed+Relation vs Seed+Relation+Diversity vs Seed+Relation+CoVisibility+Diversity vs +PoseAlign-T, all at matched object budgets where applicable.

**Risks:** PruneGround substantially weakens any novelty claim based merely on adding unnamed visual anchors. The thesis must show QA-specific support utility and budgeted rendering benefits; otherwise the contribution collapses to adaptation of existing pruning/grounding ideas.

**Scores:** Novelty 3.4/5; Expected Accuracy Gain 3.6/5; Feasibility 4.6/5; Compute Cost 4.7/5 (higher=cheaper); Fit 5.0/5; Evidence Strength 4.8/5. Target Object Reduction Ratio 50-85% is an experimental range, not a claim. Question Entity Coverage target >=95%. Context-loss risk: medium.

## Weekly top candidate
**SAFER-QA remains #1, but its novelty boundary is tightened.** Best defensible formulation is now: `QA-utility-aware unnamed support selection + fixed-budget object allocation + PoseAlign-T refinement + selective Abstract-3D rendering`.
