# Daily Proposal Research — 2026-09-23

## New retained evidence: SparseTalk (arXiv:2609.15137)

SparseTalk studies post-hoc sparsification of 3D Gaussian language fields for 3D VQA. It compares random, geometric, semantic, joint spatial-semantic, and object-based selection. On ScanQA and MV-ScanQA, strong VQA performance is retained with only a few hundred semantic embeddings; at 256 tokens it retains 0.80% of SplatTalk's 32,076-token inference input and 0.332% of the mean dense Gaussian field, while reducing decoded-feature memory by 125x. Its object-based selector distributes budget across object instances while retaining background context. Current status: arXiv preprint (submitted 2026-09-14); no official code repository verified in today's search.

## Why it matters to this thesis

SparseTalk is not a direct competitor to QASER: it sparsifies semantic Gaussian tokens after a dense 3D representation is built, is question-independent, and evaluates ScanQA/MV-ScanQA rather than SQA3D. But it supplies strong task-level evidence for two design decisions:

1. Dense/full-scene evidence is highly redundant for 3D QA.
2. Object coverage plus explicit background/context retention can outperform purely geometric or semantic global sparsification.

This strengthens the motivation for selective Abstract3D rendering, while narrowing novelty: generic object-based sparsification or 'retain context while pruning' is not enough as a contribution.

## Candidate refinement: QASER-BC (Budgeted Context Reserve)

**Research hypothesis:** Under a strict object budget, hard-retaining question seeds and relation-compatible support candidates while reserving a small number of slots for scene context will preserve QA evidence better than question-independent object coverage, semantic Top-K, or KNN.

**Changed stage:** question-conditioned object/subscene selection before Abstract3D rendering.

**Object-selection rule:** hard-retain explicit seed/referred entities; generate unnamed support candidates scene-wide using relation/question constraints; rank support by QA utility. Do not use distance as a universal gate.

**Supporting-context rule:** reserve a small fraction of K (initial ablation 10%, 20%, 30%) for context objects/background proxies not already selected, using object coverage/diversity rather than semantic similarity alone. For K=10, test 8 QA-utility + 2 context slots. Directional relations are refined only after PoseAlign-T.

**Expected benefit:** reduce catastrophic context loss at small K while preserving the main method's question conditioning; improve QA-vs-object-budget Pareto frontier.

**Implementation difficulty:** low-medium. With fixed GT boxes, no Florence/SAM/object tracking is needed; context reserve can operate directly over annotated instances and box geometry.

**Training/compute:** training-free selector; CPU geometry/ranking is negligible. GPU/VRAM remains dominated by Abstract3D + <=7B 2D VLM. No daily GPU benchmark required.

**Data/metrics:** ScanQA and SQA3D downstream QA; Object Reduction Ratio; Question Entity Coverage; Context Benefit Rate; Support Ablation Sensitivity; QA-vs-K. Supporting-Context Retention remains proxy-only without complete support-object GT.

**Ablation:** Full Scene; question-independent uniform/object coverage; Seed-only; Seed+KNN; SemanticTopK; relation-aware QA utility; QA utility + 10/20/30% context reserve; +PoseAlign-T. Match K={5,10,20} where meaningful.

**Risk:** a fixed context reserve can waste scarce slots on irrelevant objects, especially K=5. If 20-30% reserve consistently hurts, replace fixed reserve with uncertainty-gated context allocation.

**Publication potential:** moderate as a component, not standalone. SparseTalk already weakens generic sparsification/context-retention novelty; publishability depends on demonstrating question-conditioned named+unnamed support retention beats question-independent object coverage and grounding-oriented pruning at matched render budgets.

## Novelty boundary update

Do not claim generic sparsification, object-aware budget allocation, semantic/geometric diversity, or background/context retention as the main novelty. The defensible distinction remains QA-conditioned selection of named seeds plus unnamed answer-support/context objects *before* Abstract3D rendering under a strict object/render budget, with PoseAlign-T used for viewpoint-dependent relations.

## Top candidate of the week

**SAFER-QA / QASER-Utility remains #1.** SparseTalk strengthens its motivation rather than replacing it: aggressive sparsity can preserve 3D QA, but SparseTalk's selector is question-independent. The most useful experiment now is whether QASER's QA-conditioned support allocation reaches a better QA-vs-object-budget frontier than question-independent object coverage and grounding-oriented pruning.
