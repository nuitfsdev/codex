## New high-relevance paper: CitySTAR
**CitySTAR: Structured and Topology-Aware Reasoning for Open-Vocabulary Urban 3D Grounding** (arXiv:2609.19911; submitted 2026-09-17; arXiv preprint, venue not verified).

Why it matters: CitySTAR is training-free and explicitly converts language into computable constraints over entities, attributes, and spatial relations, then performs target-context topology matching / bidirectional topology verification before using candidate-centered 2D visual evidence. Although its domain is city-scale grounding rather than ScanQA/SQA3D, this is strong new evidence for the QASER-CF principle that query semantics should define constraints/search structure before geometric verification, rather than using generic semantic Top-K or nearest-neighbor gates.

## Candidate refinement: QASER-CG (Constraint-Graph Support Selection)
Hypothesis: representing each QA query as a small constraint graph (seed/referred entities + relation/attribute constraints + latent/support slots) and matching it against a lightweight graph built from fixed object labels/3D boxes can preserve unnamed supporting objects better than semantic Top-K/KNN while retaining a strict render budget.

Changed stage: question-conditioned object/subscene selection before Abstract3D rendering.

Object-selection rule:
1. Parse explicit seed entities and relation/attribute predicates from the question.
2. Build a query constraint graph; create wildcard/latent nodes where the answer/support entity is unnamed.
3. Match constraints globally against the fixed annotated object graph; geometry verifies relation predicates rather than serving as a universal distance gate.
4. Rank complete/partial graph matches and retain union of seed + matched latent/support nodes under K-object budget.

Supporting-context rule: an unnamed object is retained if it completes a high-scoring constraint path/subgraph, disambiguates competing seed instances, or is an endpoint required to verify a relation. Do not require direct noun overlap with the question.

Expected benefit: lower answer/support loss on relational questions where the answer is neither semantically similar to the full question nor close under generic KNN; interpretable reason for every retained object.

Implementation difficulty: medium. Fixed GT labels/boxes eliminate CitySTAR's expensive open-vocabulary mapping/reconstruction stage. Start with deterministic predicates from boxes and a small LLM/VLM parser only for query constraints.

Data/metrics: ScanQA + SQA3D QA metrics; ORR; Question Entity Coverage; Supporting-Context Retention; context-loss rate; answer-object retention where derivable; constraint-match coverage; average selected objects.

Compute estimate: selector itself CPU/lightweight; no training required for V0. <=7B VLM remains dominant VRAM cost (~model-dependent; do not claim an exact number without the selected quantization/backbone).

Ablation: Full Scene vs Semantic Top-K vs Seed+KNN vs CAPruner endpoints vs QASER-CF flat constraint scoring vs QASER-CG graph matching, matched K={5,10,20}; then +PoseAlign-T. Key ablation: wildcard/support nodes ON/OFF.

Risks: ScanQA/SQA3D do not directly provide complete support-object GT for every QA; query parser errors; relation graph may become dense/noisy; CitySTAR already limits novelty of generic `language -> structured constraints -> graph matching` claims.

Publication potential: medium as a standalone selector; stronger when framed specifically as pre-render QA evidence retention with unnamed support preservation under strict object/render budget and integrated with PoseAlign-T + Abstract3D.

Scores (1-5; Compute Cost higher=cheaper): Novelty 3.3 standalone / 3.7 integrated; Expected Accuracy Gain 4.0; Feasibility 4.7; Compute Cost 4.9; Fit 5.0; Evidence Strength 4.7.
Target: ORR 50-85%; QEC >=95%; SCR higher than semantic Top-K/KNN at matched K; context-loss risk medium, mitigated by QASER-R recovery.

## Novelty boundary update
Do not claim structured constraint reasoning or topology matching alone as novelty after CitySTAR. The defensible thesis gap remains: QA-specific retention of named + unnamed supporting objects **before Abstract3D rendering**, using fixed indoor object annotations/boxes, with explicit QA-vs-object-budget evaluation on ScanQA/SQA3D and viewpoint-aware verification through PoseAlign-T.

## Top candidate this week
**SAFER-QA / QASER-CF remains #1.** CitySTAR strengthens its constraint-first premise but also narrows the novelty claim. QASER-CG is the preferred structured implementation of candidate generation/support retention; QASER-R remains the recovery mechanism for missed context. The headline contribution should remain pre-render QA evidence retention under strict object/render budget, not generic graph matching.
