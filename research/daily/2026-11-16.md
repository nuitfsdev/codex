## Novelty boundary

## Candidate: Geometry-Tool Witness Gate (GTWG), secondary only
**Hypothesis:** A cheap question-type gate can distinguish queries resolvable by fixed-box geometry from queries requiring rendered visual witnesses, reducing irrelevant rendering without losing evidence.
**Stage:** Question parser, object selector, optional spatial verifier.
**Object rule:** Parse named seeds; retrieve ambiguous same-class instances semantically; scene-wide enumerate unnamed answer candidates using box relations, no hard nearest-neighbor gate. Select up to K for rendering; for geometry-only questions optionally compute answer from metadata, with explicit separate evaluation of metadata-only shortcut.
**Supporting-context:** Preserve relation endpoints, ambiguity competitors, negative/counting completeness checks and multi-hop bridges; reject claims of global completeness from a partial subscene.
**Expected:** Reduced distractors / compute, possible accuracy improvement (untested).
**Difficulty:** medium; training-free; CPU O(N^2) pairwise geometry worst case; no added selector GPU; VLM <=7B quantized target T4 16GB, actual VRAM unmeasured.
**Dataset/metrics:** ScanQA/SQA3D EM/CIDEr, ORR, QEC, independent SCR, answer-witness recall, CWC, latency, calls, peak VRAM; risk of context loss high K=5, medium/unknown K=10/20.
**Ablations:** semantic Top-K, role-aware witness selection, GTWG with/without metadata gate; K=5/10/20, M=1; compare geometry-only and visual-required subsets with matched renderer/backbone and report metadata-only separately.
**Risks:** question misclassification, GT box errors, frame ambiguity, metadata leakage, supporting-object annotation incompleteness.
**Publication potential:** low standalone, moderate only as an integrated controlled QA-vs-budget improvement.

## Candidate: Witness-Visibility View Ranking (WVVR), secondary
**Hypothesis:** Given a fixed selected physical subscene, selecting a camera by projected visibility of answer and supporting witnesses can improve QA at M=1/2 over canonical PoseAlign-T alone.
**Stage:** PoseAlign-T / view selection. **Rule:** Keep same seed+unnamed support object set S<=K; score candidate cameras for visible relation endpoints and disambiguators, penalize cropping/occlusion. **Training:** none; CPU projection + rendering; GPU inference budget unchanged at matched M. **Metrics:** ScanQA/SQA3D EM/CIDEr, witness visibility, ORR/QEC/SCR, VRAM/latency. **Ablations:** PoseAlign-T vs object visibility vs role-aware visibility, K=10, M=1/2. **Risks:** visibility proxies and viewpoint-relative reference frames; context loss if selected S already incomplete. **Publication:** low standalone due to Vantage/BEV3SR.
