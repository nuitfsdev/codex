## Novelty impact
BEV3SR is strong near-direct prior art for object-indexed memory, reference-frame formalization, metric-vs-visual routing, and object-consistent/context view selection on ScanQA/SQA3D. Do NOT claim these alone as novel. Crucial difference: our method chooses strict-budget *physical objects before synthetic abstract mesh rendering*, including unnamed answer/supporting witnesses, whereas BEV3SR retrieves existing RGB views. Main SAFER-QA hypothesis remains unproven; novelty score provisional 2.2/5 (down from 2.4).

## Candidate A: Evidence-Type-Gated Witness Allocation (ETGWA), SECONDARY
**Hypothesis:** classifying questions into geometry-complete vs visual-required can allocate K slots to unnamed answer/support objects more effectively than fixed context reserve, improving QA-vs-object-budget curve.
**Stage:** question parsing / pre-render object selection / optional verification.
**Rule:** parse named seed descriptions and open answer slots; retrieve all candidates from fixed 3D box table using frozen semantic scores and soft geometric constraints; select at most K objects by role-dependent budget; never use exact noun matching as sole criterion, and never render full scene.
**Supporting rule:** preserve relation endpoints, same-class disambiguators, and unnamed answer candidates; geometry-complete counting/existence may use full *metadata* for proof of completeness, but only selected K objects are rendered; report metadata-only route separately to avoid unfair VLM comparison.
**Benefit:** potential better witness recall and reduced visual calls, NOT measured.
**Difficulty:** medium; training-free CPU box operations O(N²) worst case; VLM <=7B quantized on T4 16GB target, unmeasured peak VRAM.
**Data/metrics:** ScanQA/SQA3D; EM/CIDEr, ORR=1-|S|/N, QEC, AWR, independent-annotation SCR/CWC, context-loss rate, inference calls, time, peak VRAM.
**Ablations:** Semantic Top-K, OpenSlotSoft, Role-Aware, fixed vs gated reserve, metadata geometry route off/on; K=5/10/20, M=1, same VLM/prompt/renderer and call budget.
**Risks:** parser error, geometry-only shortcut, unavailable complete support GT, K insufficient for counting; context loss high at K=5.
**Publication:** low standalone, medium if matched-budget Pareto gain validated.

## Candidate B: Witness-Coverage View Budget (WCVB), SECONDARY
**Hypothesis:** object-consistent + supporting-context view coverage improves answerability after selective rendering.
**Stage:** PoseAlign-T / view ranking / multi-view aggregation.
**Rule:** use unchanged K-selected objects only; rank candidate camera poses by visibility of named seed + unnamed answer + supporting relation witnesses, penalize overlap; no full-scene render.
**Supporting rule:** retain a view uniquely exposing a supporting witness or relation even if semantic seed visibility is lower.
**Benefit:** possible QA improvement at fixed M=2; difficulty medium, CPU projection O(MK) approximate plus rendering/VLM; peak VRAM unmeasured.
**Metrics/ablation:** ScanQA/SQA3D EM/CIDEr, witness visibility@M, ORR/QEC/AWR/SCR inherited, context loss, latency/VRAM; PoseAlign-only vs object coverage vs role-aware view coverage M=1/2.
**Risks:** cropping/occlusion, metadata leakage, view redundancy; publication low alone.
