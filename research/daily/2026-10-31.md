## Paper A — OneScene-Bench (NEW, strongest)
**Swathi Suhas, Anurag Das, Bernt Schiele, Jonas Fischer**, *OneScene-Bench: Do Vision-Language Models Integrate Evidence Across Views?* https://arxiv.org/abs/2610.38926 ; submitted **28 Oct 2026**, listed 30 Oct. **Status:** authors state accepted to **NeurIPS 2026 LM4RWD workshop**, NOT NeurIPS main. **Code/data:** https://github.com/swathisuhas/OneScene-Bench public; README and example.py plus six parquet files. 1,300 main manually verified examples: 200 complete-overlap counting, 300 subset-overlap, 200 complementary counting, 300 cross-view consistency, 300 cross-view spatial reasoning. Source imagery DL3DV-10K, not ScanNet/ScanQA. Two views per main example; supplemental six-view counting. **Training:** benchmark only, no training required for evaluation. **Original compute:** authors used A100 80GB for open-weight model evaluations, ~2h per task; this is NOT a minimum VRAM requirement for the benchmark. Smaller <=7B 4-bit VLM is a proposed low-resource evaluation, unmeasured.

**Critical evidence:** on complementary-view counting, twelve VLMs score **4.5–50.0%**, versus **45.5–81.5%** complete overlap. Example Qwen3-VL-32B Instruct 70.0% complete -> 34.0% complementary; cross-view consistency ~47–55.7% (near chance). Extra views and longer reasoning do not monotonically help. Strong support for **identity-preserving aggregation** and evaluating when cross-view integration is necessary, but no ScanQA/SQA3D or pre-render object selector results. Data schema has images and object names, NOT full ScanNet-style 3D object boxes or independent supporting-object GT; cannot directly compute ORR/QEC/SCR on this dataset.

**Transfer:** selected 3D object IDs are known from fixed input, so project IDs across rendered views, construct union evidence keyed by physical ID, avoid per-view count sum/max, and aggregate relation observations with pose-aware confidence. Unlike original benchmark, we can establish correspondence deterministically from fixed object IDs; must audit that VLM is not merely reading labels/metadata. OneScene-Bench can separately diagnose fusion without pretending to test pre-render selection.

## Candidate 1 — ICSMF: ID-Consistent Selected-Subscene Multi-View Fusion (secondary, new)
**Research Hypothesis:** at the same selected-object union budget K and view budget M, aggregating observations by stable annotated object IDs and relation evidence (instead of naive image concatenation or per-view counting) improves ScanQA/SQA3D multi-view QA, especially when evidence is complementary across views.

**Changed stages:** after SAFER-QA question-conditioned object selection and PoseAlign-T, modify selected-object view allocation, multi-view aggregation and spatial verification. PoseRecover, fixed annotations and instance-mesh renderer remain unchanged.

**Object-selection rule:** named seeds via frozen semantic retrieval + synonyms; unnamed answer candidates searched scene-wide via soft relation-compatible box geometry; keep complete seed–answer–support witness bundles under |S|<=K. No exact-noun hard gate, no nearest-neighbor hard gate. **Supporting-context rule:** retain reference endpoints, relation bridges, competing same-class instances and anchors needed for each question; allocate M views to cover union of selected witnesses; per-view object subsets must be subsets of S, with global union <=K. Never render all scene objects. Do not mistake absent from a view for absent from the scene.

**Aggregation:** form object-id-indexed evidence table (id, view, projected visibility, pose, class, appearance notes, relation endpoints); count physical IDs once, use geometric relation consistency across views; avoid summing per-view counts or blindly maxing. For scene-wide counting where target cardinality cannot be covered by K, explicitly mark incomplete evidence / abstain rather than claim full-scene visual counting. Global metadata is allowed for pre-render selection but symbolic box-only answer must be reported as separate baseline, not conflated with visual evidence.

**Expected benefit:** fewer cross-view identity/deduplication and relation consistency errors; potentially higher multi-view QA, unmeasured. **Difficulty:** medium (3/5). **Training:** zero. **Compute:** CPU O(MK) evidence assembly + optional O(K^2 M) relation checks, renderer M selected views; no selector GPU. VLM <=7B 4-bit T4/8–16GB VRAM is a planning target only; M=2 doubles visual evidence/token/latency relative to M=1 (not necessarily peak VRAM), measure actual. **Data:** ScanQA/SQA3D val, MV-ScanQA optional; OneScene-Bench only independent fusion diagnostic because it lacks fixed 3D boxes. **Metrics:** QA EM/CIDEr, ORR=1-|S|/N, QEC, Answer-Witness Recall, SCR (GT only with independent labels; otherwise proxy), Complete-Witness Coverage, Context-Loss Rate, unique-ID deduplication error, relation consistency, latency, peak VRAM. **Ablation:** matched K={5,10,20}, M={1,2}, same prompt/model/render/tokens; naive concatenation vs max/sum heuristic vs ID fusion vs ID fusion+relation verification; selected-only mesh, label-only, box-only controls. **Risks:** IDs visible in text may cause shortcut; selected-only render changes occlusion; small K loses unseen supports; global count cannot be visually verified when K excludes instances; more views may hurt. **Publication:** LOW standalone due multi-view identity/aggregation prior work; MEDIUM as an integrated robustness result only if matched-budget gains.

**Scores /5:** Novelty 2.3, Expected Gain 3.4, Feasibility 4.5, Compute (higher=cheaper) 4.5, Fit 4.9, Evidence 4.5. No empirical accuracy gain claimed.

## Candidate 2 — APWR: Ambiguity-Preserving Witness Reserve (RWC refinement, not new standalone method)
**Research Hypothesis:** for ambiguous named seeds with multiple same-class annotated instances, preserving competing seed hypotheses and distinguishing unnamed context within K can improve correct seed binding and QA versus single-best semantic Top-K.

**Changed stage:** question-conditioned pre-render object selection. **Object-selection rule:** frozen semantic named-seed retrieval over ALL annotations; detect same-class ambiguity from multiple instances, attributes and relation clauses; allocate a limited reserve to competing seeds and their relation endpoints; scene-wide soft geometry for unnamed answer/support slots; never exact noun-only or KNN hard gate. **Supporting-context rule:** keep distinguishing relation anchors, bridges and plausible answer endpoints; remove lowest-utility distractors when K tight, and report unresolved ambiguity if witness completeness cannot be preserved. **Expected benefit:** better seed disambiguation and unnamed support retention, not yet measured. **Difficulty:** low-medium (2.5/5). **Training:** none. **Compute:** cached semantic embeddings CPU, candidate relation scoring worst-case O(N^2), zero additional selector VRAM; 2B/4B VLM quantized 8–16GB planning only. **Data:** ScanQA/SQA3D stratified by same-class ambiguity; MIMO-Bench is only an external 2D stress-test, not a substitute. **Metrics:** ORR, QEC, Answer-Witness Recall, independent-GT SCR, Context-Loss Rate, same-class seed disambiguation accuracy, QA EM/CIDEr, VRAM/latency. **Ablation:** semantic Top-K vs RWC vs APWR; reserve 0/10/20/30%, K=5/10/20, fixed M=1 then M=2, same inference budget; random competing-instance retention. **Risks:** excessive distractor retention consumes K and harms unnamed answer recall; noisy semantic parsing. **Publication:** LOW standalone; optional RWC implementation if ambiguity failures dominate.

**Scores /5:** Novelty 1.9, Gain 3.2, Feasibility 4.7, Compute 4.8, Fit 5.0, Evidence 4.2. No benchmark measured.
