## Evidence update 1 — SceneGraphGrounder
**SceneGraphGrounder: Zero-Shot 3D Visual Grounding via Structured Scene Graph Matching** (arXiv:2605.21788, submitted 2026-05-20; preprint; code promised upon acceptance, not verified public today).

Relevant mechanism: construct a query graph with target/landmark objects and explicit relations, semantically filter candidate scene nodes, then perform constrained graph alignment / DFS matching over a persistent 3D scene graph. A VLM perspective-view tie-break resolves ambiguous matches. Reported on ScanRefer, not ScanQA/SQA3D.

### Novelty implication
- Generic `question -> query graph -> relation-aware scene graph matching` is prior work and must not be claimed as novelty.
- RCSX/SAFER-QA remains differentiated only if expansion is explicitly for **unnamed QA supporting evidence**, not merely for resolving referred targets/landmarks already represented in the query graph.
- Therefore relation-aware support expansion should be evaluated against a SceneGraphGrounder-style query-graph matching baseline, with identical object budgets.

### Transfer into current pipeline
Use GT boxes directly instead of reconstructing/segmenting the scene. Query-graph parsing can be a seed-resolution baseline/front-end. The proposed method must then expand beyond query-graph nodes to supporting candidates whose labels do not appear in the query.

Scores as a thesis component: Novelty 1.5 standalone / 2.5 as baseline; Expected Accuracy Gain 3.0; Feasibility 4.0; Compute Cost 4.0; Fit 4.0; Evidence Strength 3.5 (preprint, ScanRefer only).

## Evidence update 2 — ObsGraph
**ObsGraph: Hierarchical Observation Representation for Embodied Reasoning and Exploration** (arXiv:2606.24068, submitted 2026-06-23; under review according to author page; no verified public code today).

Relevant mechanism: room-view-object hierarchy; views preserve contextual object co-visibility and raw visual evidence; retrieval is coarse-to-fine under a bounded budget. This is not a 3D-QA selector for ScanQA, but it provides a useful principle: context can be preserved through **co-visibility/evidence neighborhoods**, not only Euclidean KNN or symbolic spatial relations.

## New candidate submodule — CoVis-Support
### Research Hypothesis
For questions whose needed supporting object is not explicitly named, objects that repeatedly co-occur with a grounded seed in high-coverage views provide a stronger context prior than pure KNN/radius and can complement relation-aware expansion without training.

### Stage changed
Supporting-context expansion inside SAFER-QA, before PoseAlign-T refinement and Abstract-3D rendering.

### Object-selection rule
1. Hard-retain seed/referred candidates.
2. Build a seed-view incidence table from available RGB-D/camera observations or renderer visibility.
3. Score each non-seed object by weighted co-visibility with seeds across informative views:
   `score_cov(o) = sum_v w(v,q) * visible(seed,v) * visible(o,v)`.
4. Combine with cheap geometry/relation compatibility, then retain top candidates under a fixed object budget.
5. After PoseAlign-T, prune directionally impossible candidates for viewpoint-dependent questions.

### Supporting-context rule
A support object can enter even when its category is absent from the question, provided it shares sufficient evidence views with a seed and is not geometrically implausible. Co-visibility is a support prior, not a final relevance label.

### Expected benefit
Better retention of physically/contextually associated objects that KNN can miss or over-represent, while still avoiding full-scene rendering. Especially plausible for `what is next to/near/by X`, local attribute comparison, and occlusion-sensitive questions.

### Difficulty / compute
Implementation difficulty: low-to-moderate if visibility tables already exist from ScanNet camera poses or the renderer. No training. Extra CPU preprocessing per scene; VLM cost unchanged or reduced due to fewer rendered objects. Expected incremental VRAM negligible; main VRAM remains the <=7B VLM inference.

### Metrics
ScanQA/SQA3D downstream QA; Object Reduction Ratio; Question Entity Coverage; object-budget vs QA curve; Context Benefit Rate; Support Ablation Sensitivity. Supporting-Context Retention remains proxy-only without explicit support-object GT.

### Required ablation
At matched object budget: Seed-only vs Seed+KNN vs Seed+radius vs Seed+relation-aware vs Seed+co-visibility vs Seed+relation+co-visibility vs +PoseAlign-T. Also ablate view weights: uniform vs question-conditioned.

### Risks
Co-visibility can retain incidental clutter; camera coverage bias may over-select large/frequent objects; supporting evidence may be spatially relevant but never co-visible with the seed. It should therefore complement, not replace, relation-aware expansion.

### Scores (1-5)
Novelty 3.0 as standalone support rule / 3.5 inside SAFER-QA combination; Expected Accuracy Gain 3.5; Feasibility 4.5; Compute Cost 4.5 (higher=cheaper); Fit 5.0; Evidence Strength 3.5.

Object-selection targets to test, not claims: Object Reduction Ratio 50-85%; Question Entity Coverage >=95%; Supporting-Context Retention unknown/proxy-only; context-loss risk medium.

## Updated novelty boundary
Do not claim novelty for:
- query-graph construction from referred entities/relations;
- semantic candidate filtering;
- relation-aware graph matching for referred-target grounding;
- selective rendering of referenced objects;
- generic question-conditioned view selection.

The plausible thesis gap remains **support-aware selection of unnamed evidence for open-ended 3D QA under a strict rendering budget**, now with two complementary support priors: symbolic relation compatibility and visual co-visibility/evidence preservation.

## Top candidate of the week
**SAFER-QA remains #1: Support-Aware Evidence Expansion for Selective Abstract 3D Rendering.**

Best current instantiation:
`seed retrieval -> relation-aware support expansion + co-visibility support prior -> fixed-budget diversity selection -> PoseAlign-T directional refinement -> selective Abstract-3D render -> <=7B VLM`.

Why still #1: SceneGraphGrounder reduces novelty of query-graph/relation matching, but it targets referred-object grounding rather than retaining unnamed QA evidence. ObsGraph independently supports the principle of preserving contextual co-visibility under a retrieval budget. Together they make SAFER-QA's contribution more precise rather than obsolete it.
