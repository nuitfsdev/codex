## Candidate: QASER-RelationWitness (refinement; not standalone novelty)
Hypothesis: QA-role-aware retention of a minimal **relation witness** (named seed, unnamed answer endpoint, necessary reference/competing context) before rendering will improve downstream ScanQA/SQA3D QA at fixed object K compared with semantic Top-K and target-grounding pruning. This is a proposal, not an observed result.
Stage: scene-wide support generation and QA-utility allocation before PoseAlign-T / selective Abstract3D.
Object rule: parse query into typed slots (answer target, explicit seed/reference, attribute, relation, frame). Enumerate ALL annotated scene objects; score relation-compatible candidate pairs using semantic class/synonym score and 3D box geometry; no exact noun or KNN hard gate. Hard-retain confident named seeds; reserve competing same-class seeds if ambiguous.
Supporting rule: for each answer candidate keep at least one plausible relation endpoint/reference witness; reserve a small number of competing answer/support candidates for disambiguation and a scene-frame object if viewpoint dependent. Do not use ScanQA object relevance as selector input.
For K in {5,10,20}, greedily allocate objects maximizing coverage of typed QA constraints and candidate diversity, then PoseAlign-T checks directional constraints. Only selected instances get mesh rendering. Under K overflow, record unmet witness constraints rather than silently treating them as satisfied.
Expected benefit: fewer target/reference swaps and missing unnamed answer endpoints; especially relational and situated QA.
Difficulty: medium; CPU-only box/graph scoring (estimated sub-second for typical tens-to-hundreds object tables, unmeasured), no added selector GPU/VRAM; downstream <=7B VLM retains its normal GPU footprint. Compute estimate is architectural, not benchmark.
Metrics: ScanQA CIDEr/EM, SQA3D EM; ORR=1-Kselected/N; Question Entity Coverage; Supporting-Context Retention (requires manual GT; otherwise proxy); Context Loss Rate; relation witness coverage, target-reference confusion, QA vs K/latency/VRAM.
Ablations: FullScene, SemanticTopK, Seed+KNN, CAPruner/PruneGround-inspired, QASER-RoleBudget, QASER+RelationWitness, minus competing candidates, minus reference witnesses, plus PoseAlign-T; same K and same VLM/prompt/render. Manual label a small held-out relation-support audit set from validation only.
Risks: box-only relations inaccurate for support/containment; ambiguous referents, GT subjective, small K drops critical witnesses. Publication potential moderate only with consistent matched-budget QA gains; typed graph/reranking already prior art.
Scores /5: Novelty 3.0 integrated; Expected Accuracy Gain 3.7; Feasibility 4.7; Compute Cost 4.9 (high=cheap); Fit 5.0; Evidence Strength 4.2. Targets only: ORR 50-85%, QEC >=95%; SCR unknown; context loss medium-high at K=5.
